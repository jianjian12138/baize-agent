# Strategic Development - 战略开发方法论

## 定位

这是项目的**通用指导思想**，整合：
- **毛泽东战略思想**：决策指导（优先级判断、资源配置、战略阶段划分）
- **标准化工程流程**：工程落地（标准阶段、产物模板、质量门禁）

## 核心框架

```
需求分析 → 技术方案 → UI设计 → 任务拆解 → 编码开发 → 开发自测 → 审查 → 冒烟 → QA → 验收 → 部署
```

## 战略层（毛泽东思想）

### 1. 抓主要矛盾

解决问题要找到关键点：
- 解决了哪个问题，其他问题会变简单？
- 哪个点打通了，整个流程就通了？
- 什么是「1」，什么是「0」？

### 2. 实践检验

不要空想，要快速验证：
- 用最小成本先做个可运行版本
- 不要等到「完美」再出手
- 迭代优于完美

### 3. 持久战

分阶段推进，不要一口气吃成胖子：
- **防御期**：搭建基础框架，核心流程通
- **相持期**：核心功能可用
- **反攻期**：完整功能上线

### 4. 群众路线

让实际执行的人参与决策：
- 开发者有发言权
- 用户有参与感
- 定期反馈调整

## 工程层（标准流程）

### Step 1: 需求分析

产出：
- `docs/需求分析.md` - 功能需求、用户故事
- `docs/需求总览.md` - 项目背景、目标、范围

### Step 2: 技术方案

产出：
- `docs/技术方案.md` - 架构、接口、数据模型

### Step 3: UI设计

**重要：必须先加载 UI-UX-Pro-Max 技能**

产出：
- `docs/UI设计规范.md` - 配色、字体、组件规范

### Step 4: 任务拆解

每个任务 2-4 小时粒度：
- `docs/任务分解.md` - WBS、依赖关系、验收标准

### Step 5: 编码开发

按任务分解执行编码

### Step 6: 开发自测

开发人员执行自测，产出：
- `docs/开发自测报告.md`

### Step 7: 审查

Code Review，产出：
- Review通过记录

### Step 8: 冒烟测试

核心功能快速验证，产出：
- `docs/冒烟测试报告.md`

### Step 9: QA测试

完整测试执行，产出：
- `docs/测试用例.md`
- `docs/测试报告.md`
- `docs/缺陷报告.md`

### Step 10: 验收

评审产出物，产出：
- `docs/验收报告.md`

### Step 11: 部署

生产环境部署，产出：
- `docs/部署文档.md`

## 关键原则

| 原则 | 说明 |
|------|------|
| 战略优先 | 先想清楚做什么，再动手 |
| 最小可行 | 先跑通核心流程，再迭代 |
| 分阶段 | 防御期→相持期→反攻期 |
| 持续验证 | 每个阶段都要有可运行产物 |
| **UI优先** | **前端开发必须先加载 UI-UX-Pro-Max 技能** |
| **全流程** | **需求→方案→UI→任务→编码→自测→审查→冒烟→QA→验收→部署** |

## 典型话术

- "这个项目我们做好长期准备，先把地基打稳。"
- "先集中力量打穿一个点，其他问题后续再处理。"
- "争论一个星期不如明天上线一个小实验。"
- "先让实际干活的人投个票，他们觉得不行就重来。"
- "没有证据的通过无效，必须有验收报告。"
- "前端开发前先加载 UI-UX-Pro-Max 设计技能。"
