# 调查研究——没有调查就没有发言权

## 核心理念

项目一切决策必须基于**一手事实**，而非经验或臆测。"没有调查就没有发言权"是项目决策的第一原则。

## 适用场景

- 项目启动前，对现状缺乏了解
- 需求不明确，各方意见分歧
- 方案争议大，无法达成共识
- 复盘归因，找不到问题根因
- 任何"拍脑袋"决策的风险场景

## 操作步骤

### Step 1: 明确调研目的

首先要回答：**我们要解决什么具体问题？**

- 写下具体的问题陈述
- 明确调研后要产出的决策选项
- 确定调研的范围和边界

### Step 2: 走向"现场"

| 调研对象 | 获取信息 | 调研方式 |
|---------|----------|----------|
| 用户 | 真实需求、痛点、使用场景 | 访谈、问卷、观察 |
| 数据 | 客观指标、行为模式 | 数据分析、日志 |
| 竞品 | 行业做法、最佳实践 | 功能对比、体验 |
| 一线执行者 | 实际困难、可落地性 | 访谈、蹲点 |

### Step 3: 用"角色分析法"识别真实诉求

不同角色对同一问题有不同的诉求：

```
用户 / 客户 → 解决什么问题？得到什么价值？
开发 / 实现者 → 技术可行性？实现成本？
运营 / 推广者 → 如何落地？需要什么支持？
管理层 → 投入产出比？风险？
```

### Step 4: 整理《现状与事实清单》

调研后，整理成结构化输出：

```markdown
## 现状与事实清单

### 已确认的事实
1. [事实1及来源]
2. [事实2及来源]

### 各方诉求
- 用户：xxx
- 开发：xxx
- 运营：xxx

### 待验证的假设
- [假设1]
- [假设2]

### 结论：基于事实的建议
[不要先入为主，基于调研结果给出建议]
```

## 典型话术

- "我们先不要急着出方案，分头去问三个最核心的用户/数据来源，明天汇总。"
- "这个需求听起来合理，但我们需要先找三个真实用户验证一下。"
- "先做个最小范围的用户调研，然后再讨论技术方案。"

## 自检清单

遇到项目障碍时，用这些问题自检：

- [ ] 我们是否掌握了足够的一手事实？
- [ ] 这些事实的来源是什么？够不够权威？
- [ ] 各方的真实诉求是什么？有没有被表达？
- [ ] 是否在基于假设而非事实做决策？
