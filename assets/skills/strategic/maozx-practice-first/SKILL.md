# 实践检验——小步快跑，从战争中学习战争

## 核心理念

任何计划都需要通过**实践修正**。不怕初步方案粗糙，只怕不敢投入实践去检验。从战争中学习战争。

## 适用场景

- 创新项目，没有先例可循
- 不确定性高，各方观点冲突
- 理论争论不休，无法达成共识
- 团队追求完美方案，一拖再拖

## 操作步骤

### Step 1: 做出"可验证版本"

用最小成本做出**MVP或试点**：

- 功能：最小可用功能
- 范围：一个用户群体/一个场景
- 时间：1周以内
- 资源：最低投入

### Step 2: 放到真实场景中跑一个短周期

```markdown
## 最小验证实验

**验证目标**: 验证某个核心假设
**验证方式**: 在真实环境跑一周
**成功标准**: 用户留存>20%，或转化率>5%
**失败标准**: 用户流失>80%
```

### Step 3: 收集偏差并分析

| 预期结果 | 实际结果 | 偏差分析 | 归因 |
|---------|----------|----------|------|
| A | A' | 偏差X | 执行问题/假设错误 |

区分：
- **执行问题**：执行不到位，可以加强
- **假设错误**：前提假设错了，需要重新设计

### Step 4: 进入下一轮实践

每轮都要产出**"可复用的错误教训"**：

```markdown
## 本轮学习

### 什么假设被验证？
- 假设A：✅/❌
- 假设B：✅/❌

### 什么错误不要再犯？
1. xxx
2. xxx
```

## 典型话术

- "争论一个星期不如明天上线一个小实验，错了我们就改，不丢人。"
- "先跑一周看看数据，比我们在家想一个月管用。"
- "这个假设对不对，我们放出去试试就知道了。"

## 自检清单

- [ ] 是否最小成本做出了可验证版本？
- [ ] 是否在真实场景中验证？
- [ ] 是否区分了"执行问题"和"假设错误"？
- [ ] 是否沉淀了可复用的错误教训？
