# 🚀 高密度需求建模：深度分析指南 (Analytical Requirement Mastery)

> [!IMPORTANT]
> **主权精髓**：本方法论蒸馏自“需求分析万字长文”。它要求白泽引擎在 Phase 1 (需求收割) 阶段，物理超越简单的文字提取，进入 **[逻辑原子化]** 与 **[时域合围]**。

---

## 1. 核心思想：逻辑即模型

需求分析不应是描述文档，而应是 **“软件运行的数字孪生”**。

### A. 实体全量核证 (Entity Matrix)
- **要求**：识别业务场景中的所有名次（实体）。
- **技能**：为每个实体建立“物理指纹”。严禁出现“相关逻辑由后端确定”等占位符。
- **示例**：在商城项目中，`PromoPrice` 不是一个数字，而是一个包含 `Constraint( < OriginalPrice )` 和 `Trigger( is_promo == true )` 的逻辑单元。

### B. 动作即状态转移 (Action-FSM)
- **要求**：将用户行为拆解为状态机（Finite State Machine）的跳转。
- **技能**：定义每个 Action 的 `Pre-condition` (前置主权) 与 `Post-condition` (结果真理)。
- **示例**：领券动作的前置条件必须包含 `remain_count > 0` 和 `status == 'active'`。

### C. 极性压力审计 (Constraint Matrix)
- **要求**：穷举所有可能导致逻辑坍缩的极性边界。
- **技能**：建立 0 占位符的约束矩阵，涵盖并发竞争、非法跳变、零/负值检测等。

## 2. 0 占位符禁令 (Zero-Placeholder Protocol)

在分析文档中，严禁出现以下任何模糊词汇。一旦发现，必须物理执行深度补强：
- “后期优化”
- “待确定”
- “由前端/后端负责”
- “通常情况下”
