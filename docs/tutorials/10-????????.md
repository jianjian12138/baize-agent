## 10.3 如何贡献代码（开发者向）

如果你想给白泽加功能、修 bug，推荐流程：

### 1) 准备环境

```bash
python install/bootstrap.py --test   # 装好并跑一遍测试
```

### 2) 写代码 + 写测试

白泽的测试哲学是 **"不造假"**：
- 用**脚本化 transport** 注入假的模型响应，**确定性**地驱动真实 Agent 循环。
- 不使用 `MagicMock` 伪造 Agent 内部行为、不使用 `assertTrue(True)` 式假绿。
- 任何"声称能用"的能力，必须有**真实跑通**的测试证据。

### 3) 跑测试 + 覆盖率

```bash
python -m pytest tests/ -q
# 带覆盖率
python -m pytest tests/ -q --cov=baize --cov-report=term-missing
```

### 4) 加规格（openspec）

每个运行时模块在 `openspec/specs/` 下都有对应规格文件。改动行为时，同步更新规格，保持"规格即事实"。

### 5) 提交与 PR

- 提交信息清晰（改了什么、为什么、怎么验证的）。
- 不提交 `.env`、密钥、`persistence/` 等（已被 git 忽略）。

## 10.4 常见问题 FAQ

**Q：白泽能离线跑吗？**
A：引擎本体能离线跑（`bench`、`index`、`memory` 都不需要模型）。但 `run`/`team` 需要模型端点——如果你用 Ollama 跑本地模型，那可以完全离线。

**Q：必须会 Python 才能用吗？**
A：使用（跑任务）不需要会写代码，会装环境、改 `.env` 即可。要**扩展/贡献**才需要 Python。

**Q：为什么我的 `run` 立刻退出码 2？**
A：多半是没配模型端点（`.env` 里 `BAIZE_MODEL_*` 为空）。这是 fail-closed 设计，不是 bug。跑 `doctor` 看具体原因。

**Q：它能帮我写整个项目吗？**
A：能做"给定目标的工程任务"（写函数、补测试、做接口、修 bug）。它不是需求分析器，大目标最好拆成明确的子任务交给 `team` 模式。

**Q：自定义工具为什么没生效？**
A：最常见原因是**装饰器没在 Agent 启动前导入**。确保 `import your_tools` 在创建 Agent 之前执行（注册表是进程级单例，详见第 6 篇）。

**Q：混沌测试会搞坏我的环境吗？**
A：混沌是**有界的、可复现的**，且默认关闭（`BAIZE_CHAOS_ENABLED=0`）。只在测试环境主动开启，生产请保持关闭。

**Q：日志里会出现我的 API Key 吗？**
A：不会。日志脱敏（redaction）会把敏感字段处理掉。但如果你的代码里自己 `print(key)`，那另算——避免在代码里打印密钥。
