# 08 · 看得见的工作

> Agent 最让人不放心的地方是**它在想什么你不知道**。
> 本篇讲白泽提供了哪些"看得见"的窗口，以及怎么把它们接进你的监控体系。

---

## 1. 四种观察方式

| 方式 | 入口 | 适合 |
| :--- | :--- | :--- |
| **终端流式输出** | `baize run` / `baize team` | 实时看每一步 |
| **会话回放** | `baize sessions <id>` | 事后复盘 |
| **REST + 指标** | `baize serve` | 接监控系统 |
| **桌面 Studio** | `baize desktop` | 图形化操作 |

---

## 2. REST 服务

```bash
python -m baize serve --port 8787
```

```bash
BAIZE_SERVE_HOST=127.0.0.1     # 默认只监听本机
BAIZE_SERVE_PORT=8787
```

打开浏览器访问 `http://127.0.0.1:8787`。

### 2.1 `/health` —— 存活探针

```bash
$ curl http://127.0.0.1:8787/health
{"status": "ok", "version": "37.0.0"}
```

**版本号是从 `baize/__init__.py` 读的**，不是写死的字符串——所以它永远不会和发布版本不一致。

Docker 镜像的 `HEALTHCHECK` 打的就是这个端点（见第 09 篇）。

### 2.2 `/metrics` —— Prometheus 指标

```bash
$ curl http://127.0.0.1:8787/metrics
# TYPE baize_plugins_loaded counter
baize_plugins_loaded 1
```

标准 Prometheus 文本格式，可以直接被 Prometheus 抓取。

指标由 `baize/observability.py` 统一管理，代码里到处能看到埋点：

```python
obs.inc("team_memory_claims")
obs.inc("team_memory_claim_conflicts")
obs.inc("context_compressions")
obs.inc("agent_loops_aborted")
obs.inc("skills_harvested")
obs.record_error("skill_harvest_errors")
```

**这些指标名本身就是文档**：看到 `agent_loops_aborted` 就知道有死循环被拦了；看到 `team_memory_claim_conflicts` 就知道有并发认领冲突。

```bash
BAIZE_OBSERVABILITY=1     # 默认开启
BAIZE_METRICS_PORT=9090   # 独立指标端口
```

### 2.3 其他端点

| 端点 | 作用 |
| :--- | :--- |
| `/` `/dashboard` | Web 工作台 |

## 3. 日志：文本或结构化

```bash
BAIZE_LOG_LEVEL=INFO
BAIZE_LOG_FORMAT=text      # 或 json
```

`logging_setup.py` 里的说明：

```
Format is chosen by BAIZE_LOG_FORMAT:
  json  - one JSON object per line (ship straight to Loki/ELK/CloudWatch)
```

切到 `json`：

```bash
BAIZE_LOG_FORMAT=json python -m baize run "..."
```

每行一个 JSON 对象，可以直接灌进 Loki / ELK / CloudWatch。

### 3.1 日志脱敏

日志写入前会经过 `redact()`：

```python
from .logging_setup import redact
```

**API key、token 之类的敏感串会被替换掉**，不会因为"日志方便排查"就把密钥写进磁盘。

## 4. 会话回放

```bash
# 列出最近会话
python -m baize sessions

# 看某个会话的完整消息流
python -m baize sessions 20260917-110148-7343c5

# 看步骤 + 耗时谱系
python -m baize sessions 20260917-110148-7343c5 --inspect
```

会话是**追加写的 JSONL**，所以：

- 进程被 `kill -9` 也不会丢已写部分；
- 可以 `tail -f` 实时看；
- 可以 `grep` 检索；
- 可以用 `--resume` 续跑。

**"可复现"的承诺就落在这个文件格式上。**

## 5. Web 工作台

`baize serve` 启动的页面是**完全自包含的**：

- **0 个** `<script src=...>` 外部脚本
- **0 个** `<link href=...>` 外部样式
- **0 个** `@import`
- **0 个** CDN 引用
- 页面里唯一的 `http://` 是 `url:'http://127.0.0.1:8787'`（一个 puppeteer 演示调用里的回环地址）

**为什么强调这个？** 因为一个"本地工具"如果从 CDN 拉 JS，就等于：

1. 离线时界面崩掉；
2. 每次打开都在向第三方泄露你的使用行为；
3. 供应链攻击面（CDN 被投毒 → 你的本地工具执行恶意代码）。

这条约束现在有测试守着（`tests/test_ui.py`），会检测任何外部资源加载器或非回环来源。

## 6. 桌面 Studio

```bash
python -m baize desktop
```

Windows 上也可以双击 `install/baize-desktop.bat`。

Studio 有 **11 个核心模块**：

```
│ 🏛️ 白泽桌面 Studio (Universal Studio V37.0.0 Prometheus)                      │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. 💬 流式对话 (SSE Live Chat)     │ 7. 🧠 分层记忆与混合 RAG (Memory & RAG) │
│ 2. 📝 Monaco 差异对比与 Hunk 合并 │ 8. 🌐 Anthropic MCP 协议工具连接器      │
│ 3. 🗺️ 多任务协同 DAG 控制台      │ 9. 🧬 达尔文元工具自繁衍企业市场        │
│ 4. 🌲 跨会话 Git-Graph 谱系树    │ 10. 🧪 系统体检与混沌抗脆弱演练台       │
│ 5. 🔍 5大语言代码符号依赖图谱     │ 11. 🛡️ 安全权限与自主度滑块 (L1~L3)     │
│ 6. 📚 技能中心 (23 in this repo) │                                         │
└─────────────────────────────────────────────────────────────────────────────┘
```

几个值得一提的：

- **Monaco Diff + Hunk 合并**：能对单个代码块做 Cherry-Pick，而不是整文件覆盖。
- **符号依赖图谱**：支持 Python / TypeScript / Rust / Go / Java 五种语言。
- **会话谱系树**：把 `--resume` 产生的会话关系画成树，看清"哪次运行是从哪次分叉出来的"。
- **自主度滑块 L1~L3**：图形化调整权限，不用手改 `.env`。

## 7. 会话分叉与压缩

Studio 里有一个"🔀 分叉与压缩"面板，对应两个概念：

| 操作 | 含义 |
| :--- | :--- |
| **分叉（fork）** | 从某个会话的状态分出一条新时间线，做假设性探索 |
| **压缩（compress）** | 把长会话的历史压掉，腾出上下文预算 |

命令行里对应的基准测试：

```
[PASS] session_fork_compress  15.1 ms  fork=20260917, compressed 142->142 tokens
```

> ⚠️ **这两个功能曾经是"死的"**：前端 JS 里有 `submitFork()` / `submitCompress()` 两个处理函数，但它们引用的输入框 `fork-parent-input` / `compress-id-input` **在 HTML 里根本不存在**——也就是说压缩功能没有任何可用的入口。
>
> 这个问题是在检查测试覆盖时发现的：原测试只断言了函数名出现在页面里，没有断言输入框存在。现在面板和输入框都补上了，测试也改成同时断言**元素存在**和**接线正确**。

## 8. 把白泽接进你的监控

一个最小可用的 Prometheus 配置：

```yaml
scrape_configs:
  - job_name: baize
    static_configs:
      - targets: ['127.0.0.1:8787']
    metrics_path: /metrics
```

Docker 部署时（第 09 篇）：

```bash
docker run -p 8787:8787 -e BAIZE_SERVE_HOST=0.0.0.0 baize-agent
curl http://localhost:8787/health
```

> **注意 `BAIZE_SERVE_HOST=0.0.0.0`**：容器里如果监听 `127.0.0.1`，`-p 8787:8787` 是**打不通**的。这个坑在 Dockerfile 里曾经真实存在——当时用的是 `ENV BAIZE_HOST` / `ENV BAIZE_PORT`，但代码读的是 `BAIZE_SERVE_HOST` / `BAIZE_SERVE_PORT`，所以那两行 ENV **完全无效**，容器静默绑在回环地址上。现已修正。

## 本篇小结

- 四种观察方式：**终端流式 / 会话回放 / REST+指标 / 桌面 Studio**。
- `/health` 返回的版本号来自单一真相源，不会漂移。
- `/metrics` 是标准 Prometheus 格式；**指标名本身就是事件字典**（如 `agent_loops_aborted`）。
- `/gate` 和 `/bench` 也是端点，监控面板可以直接展示诚实门禁状态。
- `BAIZE_LOG_FORMAT=json` 输出结构化日志，日志写入前会**脱敏**。
- 会话是追加写 JSONL，可 `tail -f`、可 `grep`、可 `--resume`。
- Web 工作台**完全自包含**（0 个外部资源加载器），有测试守着。
- 容器里必须设 `BAIZE_SERVE_HOST=0.0.0.0`，否则端口映射打不通。
