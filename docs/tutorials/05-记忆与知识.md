# 05 · 给它装上记忆与知识

> 在第 03 篇的会话记录里，你可能注意到任务还没开始，`user` 那一行就已经出现：
> `Relevant persistent memory: Retrieved context (RAG): - [skill 3.279] picasso-dev-maintainer`
>
> 本篇解释这行字是怎么来的，以及白泽的三层数据是怎么协作的。

---

## 1. 三层数据

| 层 | 存什么 | 存哪 | 用什么查 |
| :--- | :--- | :--- | :--- |
| **记忆（Memory）** | 事实、决策、假设、教训 | `persistence/logs/*.jsonl` | `baize memory recall` |
| **知识（RAG）** | 技能库文档、记忆片段 | 向量索引（内存/TF-IDF） | `baize rag search` |
| **图谱（Graph）** | 实体关系三元组 | `persistence/graph.jsonl` | `baize/graph.py` 的 `query` |

三者互补：

- **记忆**回答"**我们之前决定过什么**"；
- **RAG**回答"**哪个技能/文档和当前任务相关**"；
- **图谱**回答"**这些东西之间是什么关系**"。

---

## 2. 记忆层

### 2.1 四种记忆类别

`baize/memory.py` 定义了四个合法类别：

```python
VALID_CATEGORIES = frozenset({"fact", "decision", "assumption", "lesson"})
```

这个分类很有讲究——它对应的是**工程决策的完整生命周期**：

| 类别 | 含义 | 例子 |
| :--- | :--- | :--- |
| `fact` | 客观事实 | "Python 3.13 的 `sys.stdlib_module_names` 不含 `landlock`" |
| `decision` | 做过的决定 | "v26 和 v33 两条线不合并" |
| `assumption` | 假设（可能被推翻） | "假设用户已有 OpenAI 兼容端点" |
| `lesson` | 教训 | "覆盖率门禁不能靠调低下限来变绿" |

**把"假设"单独列出来是关键设计**：假设和事实混在一起，是最难排查的问题来源。

### 2.2 命令行操作

```bash
# 记一条
python -m baize memory log "选用 tfidf 作为默认向量后端，因为它零依赖" --tags decision,vector

# 检索
python -m baize memory recall "向量后端"

# 看统计
python -m baize memory stats
```

`memory stats` 的真实输出（干净仓库）：

```json
{
  "persistence_dir": "/path/to/repo/persistence",
  "log_files": 0,
  "events": 0,
  "notes": 0
}
```

### 2.3 让 Agent 自己记

Agent 有两个内置工具（第 06 篇详述）：

| 工具 | 作用 |
| :--- | :--- |
| `memory_log` | 把一条事件写进持久化记忆 |
| `memory_recall` | 语义检索持久化记忆 |

系统提示里明确要求它：

> `Persist important learnings with memory_log; reusable workflows with save_skill.`

**这就是"越用越懂你"的机制**：每次运行结束，重要结论落盘；下次运行时自动召回。

### 2.4 记忆压缩与归档

```bash
python -m baize memory compress --days 30
python -m baize memory archive --days 30
```

```bash
BAIZE_MEMORY_COMPRESS_DAYS=30
```

超过 30 天的日志会被压缩/归档到 `persistence/archive/`。**不是删除**——归档后的原文仍然可查。

## 3. 知识层（RAG）

### 3.1 零依赖向量后端

```bash
BAIZE_VECTOR_BACKEND=tfidf     # 默认
```

**这是零依赖承诺的一个具体体现**：RAG 需要向量检索，而主流做法是拉一个几十 MB 的 embedding 库。

白泽的默认后端是 **TF-IDF**——纯 Python 标准库实现，零依赖，够用。

想要更好的语义效果，可以接外部 embedding：

```bash
BAIZE_EMBEDDING_URL=https://your-embedding-endpoint/v1
```

> 设计取舍：**默认零依赖可用，需要时再升级**。这比"必须装 500MB 才能跑"对新手友好得多。

### 3.2 实测效果

```bash
$ python -m baize rag search "tdd"
- [skill 3.279] picasso-dev-methods
```

`3.279` 是相关度得分。

基准测试里也有对应的验证项：

```
[PASS] vector       5.2 ms  200 docs indexed, top hit d3 (0.5775)
[PASS] rag          7.3 ms  corpus=23 docs, retrieve('skill') -> 3 hits
```

### 3.3 看使用统计

```bash
python -m baize rag scores
```

## 4. 技能库：知识的主要来源

### 4.1 技能是什么

一个技能就是一个目录 + 一个 `SKILL.md`：

```
assets/skills/picasso-dev-methods/
└── SKILL.md          # 带 YAML frontmatter 的说明文档
```

`SKILL.md` 的开头是结构化元数据（frontmatter），后面是正文。

### 4.2 构建索引

```bash
$ python -m baize index build
indexed 23 skills from 1 source(s)
index file: /path/to/repo/persistence/skill_index.json
```

（干净仓库是 23 个。等第 4.5 节的自动蒸馏跑过一次之后，会变成 24 个——多出来的那个就是它自己学到的技能。）

索引文件是 JSON，可以直接看：

```bash
$ python -m baize index search "tdd"
- picasso-dev-methods [local:assets/skills]
    Use when Picasso 开发链路需要补齐方法论能力，如规划、任务拆分、TDD、系统化排障、完成前验证、代码审查处理、多代理并行与隔离策略，并要求这些方法在 skill 包内自包含、可迁移。
    /path/to/repo/assets/skills/picasso-dev-methods/SKILL.md
```

### 4.3 索引扫哪些目录

```bash
SKILL_LIBRARY_PATHS=./assets/skills
```

可以写多个（逗号分隔）。**本仓库内置 23 个技能**；指向外部技能库即可扩充。

> ⚠️ 路径必须真实存在。`doctor` 会对每个配置的路径做检查，不存在的会 FAIL——这是刻意的，防止你写错了路径却毫无察觉。

### 4.4 技能治理

```bash
python -m baize skill search "testing"     # 搜索
python -m baize skill create my-skill --description "..." --body "..."   # 创建
python -m baize skill audit                # 审计（检查 frontmatter 完整性）
```

### 4.5 学习闭环：自动蒸馏技能

这是白泽比较特别的能力。一次成功的运行结束后，引擎会尝试**把这次的做法蒸馏成一个可复用技能**：

```
   0.1s .. skill_harvested distilled skill to SKILL.md
```

实测产物：

```
user_skills/auto-创建一个-hello-baizetxt-文件内容为-hello-from-bai/SKILL.md
```

并且它**立刻进入了索引**（可以直接搜到）：

```
 -> auto-创建一个-hello-baizetxt-文件内容为-hello-from-bai | user:user_skills
```

**闭环完整路径**：任务成功 → 蒸馏 SKILL.md → 重建索引 → 下次任务被 RAG 召回 → 复用。

> 🐛 **这一环曾经是断的。** `skill_harvester.py` 调用的是 `skill_index.build()`，但模块里真正的名字是 `build_index()`。因为异常被 `except Exception` 吞成一行 warning，所以技能被写到磁盘上、却**永远进不了索引**——等于学完就忘。
>
> 这个 bug 是靠**真的跑一次 `baize run`** 才暴露出来的（日志里那行 `[harvester] failed to rebuild index`）。现在已修复，并有测试钉住（`tests/test_skill_harvest_index.py`）。

## 5. 图谱层

`baize/graph.py` 提供实体关系三元组：

```python
from baize.graph import add, query, neighbors, stats
```

存储位置：`persistence/graph.jsonl`（追加写，人类可读）。

基准测试验证：

```
[PASS] graph        4.1 ms  2 triples for node 'baize'
```

**用途**：当你需要"这个东西还和什么有关"时，图谱比向量检索更精确——向量检索找"相似"，图谱找"关联"。

---

## 6. 三层怎么协作（一次真实运行的完整链路）

以第 03 篇那次运行为例：

```
1. 任务开始
   ↓
2. 引擎自动检索：
   - 持久化记忆（memory_recall）
   - RAG 上下文（技能库 + 记忆片段）
   ↓
3. 把召回结果注入 user 消息：
   "Relevant persistent memory: Retrieved context (RAG):
    - [skill 3.279] picasso-dev-maintainer (load with load_skill: ...)"
   ↓
4. 模型带着这些上下文开始规划
   ↓
5. 需要完整技能内容时，调用 load_skill 按需加载
   ↓
6. 任务结束 → 蒸馏新技能 → 重建索引
   ↓
7. 重要结论 memory_log 落盘 → 下次被召回
```

**注意第 3 步的措辞**：注入的是**技能的名字和加载路径**，不是技能全文。真正需要时才用 `load_skill` 拉全文。

这是上下文预算的优化：23 个技能的全文可能有几十万字符，全部塞进提示会直接爆掉。**先给目录，再按需取书。**

## 7. 数据都存在哪

```
persistence/                  ← BAIZE_PERSISTENCE_DIR
├── logs/                     ← 记忆事件（JSONL）
├── sessions/                 ← 会话记录（JSONL，可 --resume）
├── archive/                  ← 压缩归档的旧日志
├── graph.jsonl               ← 知识图谱三元组
├── skill_index.json          ← 技能索引
├── skill_stats.json          ← 技能使用统计
├── skill_feedback.jsonl      ← 技能效果反馈
├── runs/                     ← 运行账本（run_ledger）
└── team_memory/              ← 多 Agent 共享黑板
user_skills/                  ← BAIZE_USER_SKILLS_DIR：自动蒸馏出的技能
projects/                     ← BAIZE_PROJECTS_DIR：Agent 生成的示例项目
```

**全部是纯文本 JSONL/JSON。** 没有二进制格式，没有需要专门工具才能读的数据库。

> 这是"可审计"承诺的基础：你可以用 `grep` 查记忆，用 `cat` 看会话，用 `jq` 分析统计。不需要信任任何黑盒。

## 8. 配置速查

| 配置键 | 默认值 | 作用 |
| :--- | :--- | :--- |
| `BAIZE_VECTOR_BACKEND` | `tfidf` | 向量后端（零依赖） |
| `BAIZE_EMBEDDING_URL` | 空 | 外部 embedding 端点（可选） |
| `BAIZE_MEMORY_COMPRESS_DAYS` | `30` | 日志压缩/归档的天数阈值 |
| `BAIZE_INDEX_FILE` | `persistence/skill_index.json` | 技能索引路径 |
| `BAIZE_USER_SKILLS_DIR` | `user_skills` | 自动蒸馏技能的输出目录 |
| `SKILL_LIBRARY_PATHS` | `./assets/skills` | 技能库扫描路径 |

## 本篇小结

- 三层数据：**记忆**（决策/事实/假设/教训）、**RAG**（技能与文档检索）、**图谱**（实体关系）。
- 记忆有四种类别，`assumption`（假设）单独分类，便于日后推翻。
- 默认向量后端是 **TF-IDF**，纯标准库、零依赖；需要更强语义时接 `BAIZE_EMBEDDING_URL`。
- 技能索引是 JSON，技能就是带 frontmatter 的 `SKILL.md`，本仓库内置 23 个。
- 学习闭环：**任务成功 → 蒸馏技能 → 重建索引 → 下次召回**（这一环曾有 bug，已修）。
- 注入上下文时**先给技能目录，再按需 `load_skill` 取全文**，这是上下文预算的关键优化。
- 所有数据都是纯文本，可以直接 `grep`/`cat`/`jq`。
