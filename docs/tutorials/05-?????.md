# 第 5 篇：给它装上记忆与知识 —— 向量检索、RAG、图谱、基准

> 适用读者：想知道白泽"怎么记住东西、怎么查资料"的小白。本篇讲清数据层的四个部件：向量检索、RAG、知识图谱、持久记忆。

---

## 5.1 为什么 Agent 需要"记忆与知识"

一个只会"凭当下对话干活"的 Agent 很弱：它不记得上次的结论、找不到历史经验、不会复用技能。白泽把"记忆"和"知识"做成了四套系统。

| 系统 | 英文 | 一句话作用 |
|------|------|-----------|
| 向量检索 | `vector` | 把文本变成"可比较的数字"，按相似度找内容 |
| 检索增强 | `rag` | 把"技能库 + 记忆"统一检索后喂给 Agent，让它更聪明 |
| 知识图谱 | `graph` | 用"三元组"（主语-关系-宾语）存结构化知识 |
| 持久记忆 | `memory` | 跨会话长期记住事件和笔记 |

---

## 5.2 向量检索（vector）—— 让"找相似"变得可能

普通搜索是"精确匹配关键词"。但你说"部署到生产"，想找的文档可能写的是"发布到线上环境"。这就需要**语义相似度**——向量检索干的就是这个。

白泽当前用 **TF-IDF**（一种经典、零依赖的关键词向量化）作为默认后端：

```bash
python -m baize rag search "deploy to prod" --top-k 5
```

> `BAIZE_VECTOR_BACKEND=tfidf`（默认）。真正的 embedding 后端（语义向量）接口已**预留**，但生产级向量库（pgvector/Chroma）尚未接入——这是 V20.1+ 的路线图项。

**它用在哪**：Agent 在思考时，会自动把"当前目标"拿去检索向量库，把相关技能/记忆注入提示词（见第 4 篇的"回忆上下文"）。

---

## 5.3 检索增强（rag）—— 把知识和记忆喂给 Agent

`rag` 模块是"统一检索入口"：它同时检索**技能索引**和**持久记忆**，按相关性打分排序，取 top-k 注入 Agent 的首轮提示。

两条命令：

```bash
# 检索与查询相关的技能和记忆
python -m baize rag search "如何写可靠的单元测试" --top-k 5

# 查看技能评分（哪些技能被用过、被评多高）
python -m baize rag scores
```

`rag scores` 会显示每个技能的使用次数与评分——这是**技能评分**功能，让常用、好用的技能被优先召回。

> 💡 对小白：你可以把 `rag search` 当成白泽内置的"智能搜索框"，问它问题，它会从自己的技能库和记忆里找最相关的内容。

---

## 5.4 知识图谱（graph）—— 用"关系"存知识

有些知识适合用"关系"表达，比如：

```
白泽 --使用--> Python标准库
单元测试 --属于--> Agent内核
登录接口 --依赖--> JWT
```

白泽的 `graph` 模块用**三元组**（主语-关系-宾语）存这类结构化知识，append-only 写入 `persistence/graph.jsonl`，并对坏行做了容错（某行损坏不影响整体）。

查看图谱统计：

```bash
python -m baize bench    # 其中包含 graph 基准项
```

> 当前图谱是"轻量骨架 + 可真实运行"的存储层。图谱的**可视化查询**在 V20.1+ 路线图中。

---

## 5.5 持久记忆（memory）—— 跨会话"长期记忆"

这是最贴近"记性"的部件。白泽把事件记进 `persistence/logs/*.jsonl`，并提供命令行管理：

```bash
# 记一条事件（带标签）
python -m baize memory log "今日完成 RAG 检索模块" --tags dev

# 记一条"值得长期记住"的笔记
python -m baize memory remember "白泽的 Verifier 必须独立验证，不能信 Executor 口头结论"

# 按关键词回忆
python -m baize memory recall 关键词

# 看记忆统计
python -m baize memory stats

# 压缩旧日志（见第 4 篇"长程记忆压缩"）
python -m baize memory compress --days 30
```

**记忆 vs 会话日志的区别**：
- 会话日志（`sessions/`）：某一次运行的完整转录，偏"过程回放"。
- 持久记忆（`logs/`、`notes.md`）：提炼后的"知识点"，偏"长期经验"。

Agent 在规划时会调用 `recall_context`，把相关记忆注入首轮提示，做到"带着经验干活"。

---

## 5.6 基准（bench）—— 证明数据层没坏

`bench` 会跑一组**确定性的核心性能测试**，其中就包含数据层项：

```bash
python -m baize bench
```

你会看到类似：

```
[PASS] vector    4.4 ms  tfidf index + retrieval
[PASS] rag       9.1 ms  skill+memory retrieval
[PASS] memory   10.4 ms  persistence recall
[PASS] graph     1.6 ms  triple store
4/4 benchmarks passed
```

每一项都是**真实跑了一遍检索/记忆操作**，不是"声称能跑"。这是白盒可信的一部分。

---

## 5.7 它们怎么配合（一次检索的全景）

当你说 `python -m baize run "给 utils.py 补测试"`：

```
        你的目标
            │
            ▼
   ┌─────────────────────┐
   │ rag.retrieve(目标)   │  ← 统一检索
   ├─────────────────────┤
   │  · vector 相似度检索 │  ← 找相似技能/记忆
   │  · 技能索引匹配      │  ← 找方法论技能
   │  · memory 回忆       │  ← 找长期经验
   └─────────┬───────────┘
             ▼
   把 top-k 相关内容注入 Agent 首轮提示
             ▼
   Agent 带着"资料"开始反思规划 + 干活
             ▼
   过程中新学到的 → memory_log / save_skill 记下来
```

---

## 5.8 配置速查（数据层）

| 配置项 | 默认 | 作用 |
|--------|------|------|
| `BAIZE_VECTOR_BACKEND` | `tfidf` | 向量后端（embedding 接口预留） |
| `BAIZE_EMBEDDING_URL` | 空 | 预留的 embedding 端点（未启用） |
| `BAIZE_MEMORY_COMPRESS_DAYS` | 30 | 多少天的日志压缩进 notes.md |

---

## 5.9 本篇小结

- **vector**：把文本变成可比较的数字（当前 TF-IDF，embedding 预留）。
- **rag**：统一检索"技能 + 记忆"，注入 Agent 提示词，并维护技能评分。
- **graph**：三元组知识图谱，存结构化关系（骨架可运行）。
- **memory**：跨会话长期记忆，`log/remember/recall/stats/compress` 全套命令。
- **bench**：确定性基准，真实证明数据层可用（4/4）。
