# 第 1 篇：认识白泽引擎 —— 它是什么、能为你做什么

> 适用读者：第一次接触白泽引擎（Baize Engine）的**纯小白**。读完本篇你会知道：白泽到底是个什么东西、为什么它不一样、你能用它做什么、以及后面 9 篇教程怎么读。

---

## 1.1 一句话定义

**白泽引擎是一套面向 AI Agent 的「白盒工程化研发操作系统」**。

拆开来说：

- **AI Agent**：能自己规划、自己调用工具（读文件、跑命令、写代码）去完成目标的 AI 程序。
- **白盒**：它的每一步思考、每一次工具调用、每一个决策都**看得见、可审计、可复现**——不像很多黑盒 Agent"它到底干了啥你不知道"。
- **工程化研发操作系统**：它不只是"一个 Agent"，而是一整套让 Agent **可靠、可观测、可部署、可验收**的运行时 + 技能包 + 工具链。

当前版本：**V24.0.0**。

---

## 1.2 它解决什么痛点

很多人玩过 ChatGPT 写代码、或用过一些"自动写代码"的 Agent。但把它们放到真实工程里，常遇到三个问题：

| 痛点 | 白泽的做法 |
|------|-----------|
| **不可信**：Agent 说"我做好了"，其实没做 / 做错了 | **NO FAKE DONE** 原则：声称完成必须有物理证据；Verifier 独立核验，失败自动重试 |
| **不可控**：危险命令、越权访问、乱改文件 | **沙箱默认开启** + 危险命令 deny-list（拒绝清单）fail-closed 拦截 |
| **不可复现**：跑一次崩溃了，状态全丢 | **会话即事实**：每次运行记成 JSONL 日志，崩溃不丢状态，可续跑 |

---

## 1.3 双层架构：它是怎么组织的

白泽采用**两层混合架构**，这是它最核心的设计思想：

```
┌──────────────────────────────────────────────────────────┐
│  第一层：规约与技能（给人/给 AI 客户端"读"的）              │
│  AGENT.md（操作协议）  SKILL.md（流水线规约）              │
│  assets/skills/（本地方法论技能）                          │
│  外部技能库（SKILL_LIBRARY_PATHS，249 个唯一技能）          │
├──────────────────────────────────────────────────────────┤
│  第二层：baize 运行时（真正"跑起来"的程序，纯标准库）      │
│  agent / llm / tools / orchestrator / memory / rag / ...   │
└──────────────────────────────────────────────────────────┘
```

- **第一层**是"方法论"：把人类沉淀的好经验（怎么调研、怎么写代码、怎么测试）写成技能文件，AI 加载后照着做。
- **第二层**是"引擎"：真正执行任务、调模型、调工具、记日志的代码。

> 💡 小白理解：第一层像"员工手册 + 培训教材"，第二层像"生产车间 + 流水线"。两者配合，才能让 AI 既"懂方法"又"能干活"。

---

## 1.4 它从哪来：hermes-agent 与 pi-agent 的影子

白泽不是凭空造的，它吸收了两个知名开源 Agent 项目的优点，并补齐了它们的工程短板：

- **hermes-agent** 给了它：自主循环（reason→tool→observe→repeat）、模型无关客户端、自进化技能（学会的东西能存下来复用）。
- **pi-agent** 给了它：极简内核 + 原语工具、append-only JSONL 会话 + 断点续跑、渐进式披露（用到哪个技能才加载哪个）。

白泽在二者之上，**新增并强化了**：插件系统、可观测性（Prometheus 指标）、TUI 进度、Web 仪表盘、CI、容器化、向量检索 + RAG、多 Agent 协作记忆、混沌韧性测试。

---

## 1.5 一个最关键的特性：零第三方依赖

> **白泽运行时只依赖 Python 标准库，不需要安装任何第三方包。**

这意味着：
- 安装极简（复制一个 `.env` 就能跑，见第 2 篇）。
- 没有"依赖地狱"，不会因为某个库版本冲突而崩。
- 部署到任意装了 Python 3.10+ 的机器即可运行（Docker 镜像也很小）。

唯一需要第三方包的地方是**跑测试**（pytest / pytest-cov），这不影响使用。

## 1.6 白泽能做什么 / 不能做什么

**✅ 能做的事：**
- 给定一句话目标（如"给 utils.py 补齐单元测试"），自动规划、写代码、跑测试、自检。
- 多 Agent 团队协作（一个负责规划、一个负责干活、一个负责验收）。
- 检索自己的"记忆"和"技能库"来辅助决策（RAG）。
- 通过 Web 仪表盘实时监控运行进度。
- 接入 CI/CD，像普通软件一样做持续集成与容器部署。

**❌ 目前不能 / 不建议做的事：**
- 不是聊天机器人：它不是用来跟你闲聊的，而是用来"完成工程任务"的。
- 没有真实向量库后端：当前向量检索是 TF-IDF（关键词级），生产级语义检索（pgvector/Chroma）在路线图中，尚未落地。
- 没有多模态微调能力（V19 路线图里的 P2 项，未做）。
- 需要你自备一个 OpenAI 兼容的模型端点（它自己不提供模型，只负责"调度"模型）。

## 1.9 本篇小结

- 白泽引擎 = 白盒工程化的 AI Agent 研发操作系统，当前 V24.0.0。
- 双层架构：第一层"方法论技能"，第二层"真实运行时"。
- 三大卖点：**可信（NO FAKE DONE）、可控（沙箱 + deny-list）、可复现（JSONL 会话）**。
- **零第三方依赖**是它工程上的一大优势。
- 它不是聊天机器人，而是"完成工程任务的引擎"。
