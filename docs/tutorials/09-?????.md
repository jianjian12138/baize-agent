# 第 9 篇：部署到生产 —— Docker / CI / 结构化日志 / 混沌测试

> 适用读者：想把白泽用在真实环境、或做 DevOps/运维的小白。本篇讲清如何把它工程化地跑起来、监控起来、并验证它的韧性。

---

## 9.1 白泽为什么"好部署"

回想第 1 篇：**零第三方运行时依赖**。这意味着：
- 不需要 `pip install` 一堆包，没有依赖冲突。
- Docker 镜像可以很小、很稳。
- 随便一台装了 Python 3.10+ 的机器都能跑。

工程化部件都在 `baize/` 里：`observability`（指标）、`logging_setup`（日志）、`chaos`（混沌）、`plugin`（插件）、`config_schema`（配置校验）。

---

## 9.2 用 Docker 跑起来

项目根目录有 `Dockerfile`，特点：
- **非 root 运行**：容器里用普通用户跑，降低被攻破风险。
- **/data 可写**：持久化目录挂载点可写。
- **健康检查**：自带 `HEALTHCHECK`，配合编排系统自动重启异常容器。

构建与运行：

```bash
# 构建镜像
docker build -t baize:20.0.0 .

# 运行（挂载持久化目录、映射仪表盘端口）
docker run -d \
  -p 8787:8787 \
  -v $(pwd)/persistence:/data/persistence \
  -v $(pwd)/.env:/app/.env:ro \
  baize:20.0.0 \
  python -m baize serve --port 8787
```

> 注意：`.env` 含密钥，挂载时用 `:ro`（只读），且**不要**把它提交进镜像或仓库。

`.dockerignore` 已配置，避免把 `persistence/`、`.env`、`__pycache__` 等无关内容塞进镜像。

## 9.3 持续集成（CI）

项目有 `.github/workflows/ci.yml`，做这些事：
- **跨 OS × Python 矩阵**：在多个操作系统（Linux/macOS/Windows）和 Python 3.10–3.13 上跑测试，确保兼容性。
- **零依赖校验**：确认运行时真的没有第三方依赖。
- **覆盖率门禁**：测试覆盖率必须达标（当前阈值 **80%**）。
- **Docker 构建**：验证镜像能正常构建。

本地也能用 `Makefile` 跑等价流程：

```bash
make test          # 跑测试
make ci            # 跑 CI 等价检查（视 Makefile 定义）
```

> 关于覆盖率门槛：V20 实测 80%，所以 CI 阈值设为 80%。这是有意为之——防御式 fail-closed 分支（大量"异常/拒绝"路径）本身难被测试覆盖，硬设 85% 会让流水线**必然失败**。这点在交付时已经过甲方确认。

## 9.4 结构化日志与脱敏

白泽支持两种日志格式：

```env
BAIZE_LOG_FORMAT=text     # 人类可读的文本日志（默认）
BAIZE_LOG_LEVEL=INFO      # DEBUG | INFO | WARNING | ERROR | CRITICAL
```

```env
BAIZE_LOG_FORMAT=json     # 机器可读的 JSON 结构化日志
```

**为什么用 JSON 日志**：在容器/云环境里，JSON 日志能被日志收集系统（Loki、ELK 等）直接解析、检索、告警。

**脱敏很重要**：日志里可能偶然出现密钥、token。白泽的 `logging_setup` 会对敏感字段做**脱敏**（redaction），不会把明文密钥写进日志。这是 P0 级安全要求。

## 9.5 可观测性（observability）

`baize/observability.py` 提供：
- **span**（调用链）：记录一次模型调用/工具调用的耗时。
- **指标**（metrics）：如 `llm_calls`（模型调用次数）、`llm_errors`（模型错误数）。
- **Prometheus 导出**：`/metrics` 端点（见第 8 篇）把这些指标以文本格式暴露。

你可以用 Prometheus + Grafana 搭建监控面板，长期观察白泽的：
- 模型调用频率与错误率
- 任务成功率
- 工具调用分布

## 9.6 混沌测试（Chaos）—— 证明它"抗造"

这是白泽"白盒可信"最有特色的一环。普通项目说"我们的系统很稳"，但拿不出证据。白泽用 `baize/chaos.py` **真的注入故障**，验证 Agent 不会因为一次网络抖动就崩。

混沌能注入的故障包括（测试期开启）：
- 模拟模型调用失败（让重试逻辑真的被触发）。
- 模拟工具超时。
- 注入网络异常（SSL 错误等），验证 LLM 重试从"窄异常"硬化为"全捕获"（V20 修复过真实缺陷：旧版只捕获少数异常类型，任意传输异常会穿透杀死 Agent）。

开启方式（**仅测试用**）：

```env
BAIZE_CHAOS_ENABLED=1
BAIZE_CHAOS_FAILURE_RATE=0.3     # 30% 概率注入故障
BAIZE_CHAOS_SEED=12345            # 固定种子，让混沌可复现
```

> ⚠️ 混沌是**破坏性测试**，只在测试/验证环境开启，**绝不要**在生产开着跑。

测试套件里有真正用混沌驱动 Agent 循环的案例（脚本化 transport 注入故障），确认 Agent 在故障下仍能优雅降级、失败有界、不崩溃。

## 9.7 配置校验（config_schema）

`baize/config_schema.py` 对配置做**强类型校验**：
- 数值范围（`int_range`）：比如某个值必须在 1–3650 之间。
- 枚举（`enum`）：只能是预设的几个值之一。
- 布尔、JSON 等。

如果 `.env` 里填了非法值（比如把端口写成负数、把开关写成"也许"），doctor / 启动时会被**校验出来并报错**，而不是悄悄用错值运行。这把"配置错误"挡在了运行前。

---

## 9.8 运维检查清单

部署到生产前，确认：

- [ ] `python -m baize doctor` 通过
- [ ] `.env` 的模型端点、API Key 正确且**不在镜像/仓库里**
- [ ] `BAIZE_WORKSPACE_DIR` 沙箱限制开启（`BAIZE_ALLOW_OUTSIDE_WORKSPACE=0`）
- [ ] 日志用 `json` 格式 + 脱敏开启
- [ ] `/metrics` 接入监控（Prometheus/Grafana）
- [ ] 容器非 root + 健康检查
- [ ] 混沌测试**只在测试环境**开（`BAIZE_CHAOS_ENABLED=0` 生产）
- [ ] 配置值通过 `config_schema` 校验

---

## 9.9 本篇小结

- **Docker**：非 root + `/data` 可写 + 健康检查，`docker build/run` 即可。
- **CI**：跨 OS × Python 3.10–3.13 矩阵、零依赖校验、80% 覆盖率门禁、Docker 构建。
- **日志**：`text`/`json` 两种格式，敏感字段**脱敏**（P0 安全）。
- **可观测性**：span + 指标 + `/metrics` Prometheus 导出。
- **混沌**：真注入故障验证韧性（LLM 重试全捕获已修复），**仅测试环境开**。
- **配置校验**：`config_schema` 强类型校验，把配置错误挡在运行前。
