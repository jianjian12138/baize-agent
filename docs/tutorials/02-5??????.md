# 第 2 篇：5 分钟装好环境 —— 从零开始的安装与配置

> 适用读者：刚拿到项目代码、还没跑起来过的小白。本篇手把手教你装好环境、配好模型，并通过"环境门禁"。

---

## 2.1 你需要准备什么

| 条件 | 说明 |
|------|------|
| **Python 3.10 及以上** | 白泽只用标准库，但要求 Python ≥ 3.10（3.10 / 3.11 / 3.12 / 3.13 均可） |
| **一个 OpenAI 兼容的模型端点** | 如 OpenAI、OpenRouter、Ollama、vLLM、本地网关等。它是白泽"大脑"的来源 |
| **Git（可选）** | 如果你是从 GitHub 克隆的 |

> 💡 如果你只想"看看白泽长什么样"，不配模型也能跑 `doctor`、`index`、`bench`、`rag` 等命令（见第 3 篇）。但**真正让 Agent 干活必须配模型**。

### 检查 Python 版本

```bash
python --version
# 或
python3 --version
```

如果显示 `Python 3.10.x` 或更高，即可。若低于 3.10，请先升级 Python。

如果你是从 Git 仓库拿到的：

git clone https://github.com/jianjian12138/baize-agent.git

## 2.3 三种安装方式（任选其一）

白泽追求"类 hermes / pi 的一键体验"，安装非常简单。

### 方式 A：一键引导脚本（推荐小白）

```bash
python install/bootstrap.py
```

这个脚本会自动：
1. 检查 Python 版本是否达标；
2. 从 `.env.example` 复制出 `.env`（如果还没有）；
3. 运行 `baize doctor` 环境门禁；
4. 提示你后续怎么用。

如果你还想一键跑测试，加 `--test`：

```bash
python install/bootstrap.py --test
```

如果想跳过门禁（不推荐）：

```bash
python install/bootstrap.py --skip-doctor
```

### 方式 B：手动复制 .env（最简单）

```bash
cp .env.example .env
```

### 方式 C：用安装脚本（Windows 批处理 / Linux 脚本）

项目 `install/` 目录还提供了：
- `install.bat`（Windows 双击运行）
- `setup.sh`（Linux / macOS 运行）

详见的 `install/开发环境安装指引.md`。

> ⚠️ 重要提醒：`.env` 里会放你的**模型 API Key**，它已被 git 忽略，**永远不会被提交到代码库**。请务必保管好，不要把它贴到公开地方。

---

## 2.4 配置 .env（最关键的一步）

用编辑器打开根目录的 `.env` 文件。你需要重点配置三项：

### (1) 模型端点（必填，否则 Agent 拒绝启动）

```env
# 任意 OpenAI 兼容的 chat-completions 端点
BAIZE_MODEL_BASE_URL=https://api.openai.com/v1
BAIZE_MODEL_NAME=gpt-4o-mini
BAIZE_MODEL_API_KEY=你的真实key填这里
```

> 如果你用 Ollama 本地模型，长这样：
> ```env
> BAIZE_MODEL_BASE_URL=http://localhost:11434/v1
> BAIZE_MODEL_NAME=llama3.1
> BAIZE_MODEL_API_KEY=ollama        # Ollama 一般不校验 key，填任意值即可
> ```

> 如果你用 OpenRouter：
> ```env
> BAIZE_MODEL_BASE_URL=https://openrouter.ai/api/v1
> BAIZE_MODEL_NAME=openai/gpt-4o-mini
> BAIZE_MODEL_API_KEY=sk-or-...
> ```

### (2) 外部技能库路径（可选，但建议）

白泽自带一批"方法论技能"。如果你想引用**外部的技能库**（别人写好的技能集合），配置：

```env
SKILL_LIBRARY_PATHS=D:/picasso-dev-skill/skills,D:/skills
```

> ⚠️ 注意：doctor 门禁会**真实探测这些路径是否存在**。如果路径不存在，`doctor` 会报错。所以：
> - 没有外部技能库就**留空**（`SKILL_LIBRARY_PATHS=`）；
> - 填了路径就必须保证路径真实存在，否则门禁过不了。

### (3) 常用可调参数（都有默认值，先不用改）

```env
BAIZE_AGENT_MAX_STEPS=24        # 单次运行最多思考-行动循环次数
BAIZE_LLM_MAX_RETRIES=2         # 模型调用失败重试次数
BAIZE_WORKSPACE_DIR=./          # 工具沙箱根目录（工具不能越出此目录）
BAIZE_ALLOW_OUTSIDE_WORKSPACE=0 # 默认 0=禁止工具访问沙箱外文件
```

## 2.5 运行"环境门禁" doctor

配置完 `.env`，运行：

```bash
python -m baize doctor
```

它会逐项检查环境（Python 版本、.env 配置、模型端点可达性、技能库路径、目录权限等），并给出类似：

```
Baize doctor — environment checks

  • Python version ............ OK (3.13.12)
  • .env present ............... OK
  • model endpoint ............. OK (gpt-4o-mini @ https://api.openai.com/v1)
  • skill library paths ........ OK (0 configured)
  • persistence dir ............ OK
  • sessions dir ............... OK

PASSED — environment ready.
```

如果某项是 `WARN` 或 `FAIL`，它会告诉你**具体哪一项、为什么**。按提示修复即可。

> 💡 doctor 是"白盒可信"的第一道关：任何 Agent 运行前都建议先跑 doctor。

---

## 2.6 常见问题排错

| 现象 | 原因 | 解决办法 |
|------|------|---------|
| `command not found: python` | 没装 Python 或没加环境变量 | 安装 Python 3.10+ 并勾选 "Add to PATH" |
| `python` 指向 Python 2 | 系统里 python 是老版本 | 改用 `python3` |
| `doctor` 报 `model endpoint FAIL` | `.env` 里没填或填错 BAIZE_MODEL_* | 检查 2.4 节三项是否填对 |
| `doctor` 报 `skill library paths FAIL` | SKILL_LIBRARY_PATHS 填了不存在的路径 | 删掉/修正该路径，或留空 |
| 配了模型仍 `doctor` 报 FAIL | API Key 无效 / 端点不通 | 换 key 或换网络环境 |
| `.env` 改了不生效 | 没保存 / 进程缓存 | 保存文件后重新开终端再跑 |

## 2.7 验证安装成功

跑一个**不需要模型**的命令确认引擎本身正常：

```bash
python -m baize bench
```

应看到类似：

```
[PASS] vector    4.4 ms  tfidf index + retrieval
[PASS] rag       9.1 ms  skill+memory retrieval
[PASS] memory   10.4 ms  persistence recall
[PASS] graph     1.6 ms  triple store
4/4 benchmarks passed
```

看到 `4/4 benchmarks passed` 就说明引擎本体装好了 ✅。

## 2.8 本篇小结

- 安装只需 `python install/bootstrap.py` 或 `cp .env.example .env`。
- **必须配置** `BAIZE_MODEL_BASE_URL` / `BAIZE_MODEL_NAME` / `BAIZE_MODEL_API_KEY` 三项，否则 Agent 不会启动（fail-closed，exit 2）。
- `SKILL_LIBRARY_PATHS` 填了就必须存在，否则 doctor 报错。
- 配完跑 `python -m baize doctor`，看到 `PASSED` 才算环境就绪。
- `.env` 含密钥，已被 git 忽略，**不要提交、不要外泄**。
