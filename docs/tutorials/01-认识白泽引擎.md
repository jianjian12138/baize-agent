# 01 · 认识白泽引擎

> 本篇讲清楚三件事：它**是什么**、**为什么和别的 Agent 框架不一样**、**能做什么 / 不能做什么**。
> 读完之后你应该能判断：这个项目值不值得你继续投入时间。

---

## 1. 一句话定义

白泽引擎（Baize Agent）是一个**零运行时依赖**的自主编码 Agent 引擎：

- 语言：纯 Python，**只使用标准库**
- 版本：**V37.0.0 Prometheus**（`baize/__init__.py` 是唯一版本真相源）
- 形态：既能当**命令行工具**用（`baize run`），也能当**库**用（`import baize`），还能当**服务**跑（`baize serve`）

"零运行时依赖"不是一句宣传，而是一条**可被 CI 强制执行**的契约。它意味着：

```bash
pip install baize-agent   # 不会拉取任何第三方包
python -c "import baize"  # 在一个"裸"解释器上必须成功
```

这条契约由 `scripts/check_zero_deps.py` 把关。它只对**模块级**的第三方 import 报错——因为只有模块级 import 才会在 `import baize` 时执行；被 `try/except ImportError` 包住的、放在函数体里的、以及 `TYPE_CHECKING` 里的可选 import 是被允许的，检查器会把它们**列出来但不判失败**。

## 2. 它为什么和别的框架不一样

大部分 Agent 框架的差异点在"能力清单"：支持多少模型、多少工具、多少插件。白泽的差异点在**可信度**。

### 2.1 诚实门禁（NO FAKE DONE）

项目里有一条硬规则，写在 `SOUL.md` 里：

> 没跑过的运行、没拿到的凭据、没部署的环境、没真实验证的指标，一律报 `NEEDS_*` 或直接说"没做"。

这条规则不是文档里的口号，它被编译成了可执行的门禁：

```bash
python -m baize gate
```

真实输出（2026-09-17 在一个全新 clone 里跑完 `make cov` 之后实测；覆盖率数字随每次提交变化）：

```
NO FAKE DONE GATE
  manifest : PASS
  coverage : PASS (86.5% >= 85%)
  quality  : 1.0 (threshold 0.8) PASS
    - runnable: 1.0
    - coverage_clarity: 1.0
    - composition: 1.0
    - loop_integrity: 1.0
    - locatability: 1.0
    - maintainability: 1.0
  overall  : PASS
```

注意最后一行：**overall 是 PASS**——但前提是你先跑过 `make cov`。没有覆盖率数据时它不会假装通过，而是报 `coverage : UNKNOWN`。

这个门禁曾经是红的：覆盖率 77.4%，低于自己定的 85%。它把这个事实直接印在门禁输出里、印在 README 徽章上、印在 `CONTRIBUTING.md` 里，而不是把数字改小来变绿。后来查清了根因——那 24 个文件一直没被提交——补提交后门禁转绿。

这就是白泽的核心气质：**它报的是它测到的东西。它宁愿显示红色，也不愿意把数字改小来变绿。**

### 2.2 三条自证机制

| 机制 | 命令 | 它证明什么 |
| :--- | :--- | :--- |
| 真相源门禁 | `python scripts/sync_truth.py --check` | 版本号、测试数在所有文档里是否一致 |
| 卫生门禁 | `python scripts/check_hygiene.py` | 有没有 `__pycache__`、探针脚本被误提交进 git |
| 零依赖门禁 | `python scripts/check_zero_deps.py` | `import baize` 是否真的只依赖标准库 |

三个门禁 + 覆盖率门禁，一条命令全跑：

```bash
make gate     # deps → truth → hygiene → cov（便宜的检查先跑）
```

**设计意图**：让"说过的话"和"代码的事实"不可能长期不一致。改了版本号却忘了改文档？`truth` 门禁会在几秒内失败，并告诉你哪个文件的哪一行对不上。

## 3. 两层架构

```
┌────────────────────────────────────────────────────────────┐
│  白泽桌面 Studio（11 个核心模块）                          │
│  Monaco Diff · 可视化 DAG · 多语言图谱 · MCP 连接器        │
└──────────────────────────┬─────────────────────────────────┘
                           │ HTTP / SSE 流式推送
┌──────────────────────────▼─────────────────────────────────┐
│  白泽核心研发引擎（纯 Python 标准库）                      │
├──────────────────────────┬─────────────────────────────────┤
│  Asyncio Swarm 并发引擎  │  多语言代码符号图谱             │
│  （确定性模拟，无隔离）  │  （Python/TS/Rust/Go/Java）     │
├──────────────────────────┼─────────────────────────────────┤
│  AST 语义上下文剪枝器    │  评审票数门槛仲裁台             │
├──────────────────────────┼─────────────────────────────────┤
│  常驻 PowerShell 进程池  │  Anthropic MCP 协议支持         │
└──────────────────────────┴─────────────────────────────────┘
```

- **核心引擎**：`baize/` 目录，纯标准库。所有能力都从这里来。
- **Studio**：通过 `baize serve` 启动的 Web 界面，`http://127.0.0.1:8787`。

**关键点**：Studio 是核心引擎的**消费者**，不是必需品。你可以一辈子只用命令行。

## 4. 能力边界（能做什么 / 不能做什么）

### ✅ 能做的

| 能力 | 入口 |
| :--- | :--- |
| 单任务全自主执行（思考→编码→测试→自愈） | `baize run "<目标>"` |
| 多角色协作（Director → Executor → Verifier） | `baize team "<目标>"` |
| 持续交互式 REPL | `baize chat` |
| REST 服务 + Web 工作台 | `baize serve` |
| 假设性时间线分叉探索 | `baize speculative "<目标>"` |
| 定时自动化任务 | `baize automations` |
| 技能库治理（构建/搜索/创建/审计） | `baize skill` |
| 环境体检 | `baize doctor` |
| 确定性基准测试 | `baize bench` |
| 诚实门禁 | `baize gate` |

完整的子命令有 **28 个**，用 `python -m baize --help` 查看。

### ❌ 不能做的（以及为什么）

| 做不到 | 原因 |
| :--- | :--- |
| 自带大模型 | 项目**只做引擎**，你需要自备任意 OpenAI 兼容端点。未配置模型时 `baize run` 会**拒绝启动**并提示你跑 `baize setup`。 |
| Windows 上的 OS 级硬隔离 | Windows 受限令牌实现成本极高，项目选择**诚实地降级**：`baize doctor` 会报 `os sandbox - mechanism=logical-only`，明确告诉你只有逻辑层防护（deny-list + 工作区约束），而不是假装有沙箱。 |
| 保证 100% 覆盖率 | 不保证。它只承诺**报出真实数字**：如果覆盖率数据文件比源码还旧，门禁会拒绝给结论（`cannot verify`），而不是拿旧数据凑一个绿色或红色。 |

## 5. 核心事实速记

以下数字**全部来自本机实测**，不是抄文档：

| 项目 | 实测值 | 怎么测的 |
| :--- | :--- | :--- |
| 版本 | V37.0.0 Prometheus | `python -m baize --version` |
| 运行时依赖 | **0**（纯标准库） | `python scripts/check_zero_deps.py` |
| 测试用例 | **1298 个收集**（通过/跳过数由 `make test` 打印） | `pytest tests/ --collect-only` |
| 覆盖率 | **见 `python scripts/coverage_gate.py` 的输出**（下限 85%） | `python scripts/coverage_gate.py` |
| 内置工具 | **13 个**（开启 `BAIZE_ALLOW_FETCH_URL=1` 后 14 个） | `baize/tools.py:default_registry()` |
| 内置技能 | **23 个** `SKILL.md` | `find assets/skills -name SKILL.md` |
| 配置项 | **54 个** `BAIZE_*` 键 | `baize/config.py:_DEFAULTS` |
| 基准测试 | **15/15 通过** | `python -m baize bench` |
| CLI 子命令 | **28 个** | `python -m baize --help` |

> 覆盖率一行**故意不写数字**。这里原本写着 `77.4%（门禁 RED）`，那个值在写下的当天就开始过期：它的根因是 24 个文件一直没被提交，补提交后门禁转绿，而这一行还在宣布"红"。现在只有"测试用例"一行带数字，因为它是唯一一道便宜门禁能实时校验的数字（`scripts/sync_truth.py --check` 会钉住它）。

> ⚠️ 那 2 个"跳过"的测试不是被忽略的失败。它们需要一个本环境不具备的能力（PowerShell 启动绝对路径可执行文件），跳过时会打印明确原因。详见第 10 篇。

## 6. 分支拓扑（重要）

这个仓库有**两条互不合并的历史线**：

| 分支 | 内容 | 状态 |
| :--- | :--- | :--- |
| **`v30-dev`** | V30 → V37.0.0 Prometheus 线 | **默认分支 · 活跃开发** |
| `main` | V26.0.0「闭环事实内核」架构重构线 | 冻结存档 |
| `test` | V33.0.0 升级线 | 冻结存档 |

`main`(V26) 与 `test`(V33) 是对同一份 V25 架构的两条**平行重构**，**互不包含，不做合并**。

如果你是第一次来：**待在 `v30-dev` 分支**，读这份教程，忽略另外两个分支。

## 本篇小结

- 白泽是一个**零运行时依赖**的纯标准库 Agent 引擎，当前版本 **V37.0.0 Prometheus**。
- 它最大的特点是**诚实**：门禁只报它测到的东西——数据比源码旧就说 `cannot verify`，覆盖率不够就显示红色，徽章显示的是"通过数/总数"而不是 `100% passed`。
- 两层架构：核心引擎（命令行/库）+ 可选 Studio（Web 界面）。
- 它不自带模型，需要你自备一个 OpenAI 兼容端点。
- 仓库有两条互不合并的分支线，你现在应该待在 `v30-dev`。
