# 03 · 跑通你的第一个任务

> 目标：让白泽**真的**自主完成一件事，并学会读懂它打印的每一行。
> 本篇的输出全部是**真实运行结果**，不是示例。

---

## 1. 准备一个"假模型"来练习

想练手又不想花钱？用一个几十行的桩服务就够——它说的是同一套 OpenAI 协议，所以引擎走的是**真实代码路径**（真实工具调用、真实会话落盘、真实界面渲染），只有模型的回答是脚本化的。

把下面这个文件存成 `stub_model.py`：

```python
"""一个脚本化的 OpenAI 兼容端点，仅用于学习。"""
import json, sys, threading
from http.server import BaseHTTPRequestHandler, HTTPServer

PORT = int(sys.argv[1]) if len(sys.argv) > 1 else 8899
STATE = {"n": 0}

def _call(cid, name, args):
    return {"id": cid, "type": "function",
            "function": {"name": name, "arguments": json.dumps(args)}}

SCRIPT = [
    {"content": "I will create the file first.",
     "tool_calls": [_call("c1", "write_file",
                          {"path": "hello_baize.txt",
                           "content": "Hello from Baize!\n"})]},
    {"content": "Now I will read it back to verify.",
     "tool_calls": [_call("c2", "read_file", {"path": "hello_baize.txt"})]},
    {"content": "Done. I created hello_baize.txt and verified it.",
     "tool_calls": None},
]

class H(BaseHTTPRequestHandler):
    def do_POST(self):
        req = json.loads(self.rfile.read(int(self.headers.get("Content-Length", 0))) or b"{}")
        i = STATE["n"]; STATE["n"] += 1
        step = SCRIPT[min(i, len(SCRIPT) - 1)]
        msg = {"role": "assistant", "content": step["content"]}
        if step["tool_calls"]:
            msg["tool_calls"] = step["tool_calls"]
        out = json.dumps({"id": f"s{i}", "object": "chat.completion",
                          "model": req.get("model", "stub"),
                          "choices": [{"index": 0, "message": msg,
                                       "finish_reason": "stop"}]}).encode()
        self.send_response(200)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(out)))
        self.end_headers(); self.wfile.write(out)
    def log_message(self, *a): pass

HTTPServer(("127.0.0.1", PORT), H).serve_forever()
```

启动它（另开一个终端窗口）：

```bash
python stub_model.py 8899
```

然后告诉白泽用它：

```bash
export BAIZE_MODEL_BASE_URL="http://127.0.0.1:8899"
export BAIZE_MODEL_NAME="stub-model"
export BAIZE_MODEL_API_KEY="stub-key"
```

> ⚠️ **如果你在代理后面**，记得让回环地址绕过代理，否则请求会被代理吞掉：
> ```bash
> export no_proxy="127.0.0.1,localhost"
> ```
> 不设的话你会看到 `HTTP Error 502: Bad Gateway`，而桩服务根本没收到请求。

## 2. 跑第一个任务

```bash
python -m baize run "创建一个 hello_baize.txt 文件，内容为 Hello from Baize!，然后读回来验证"
```

**真实输出：**

```
session: 20260917-110148-7343c5
   0.0s -> tool     write_file({"path": "hello_baize.txt", "content": "Hello from Baize!\n"})
   0.0s -> tool     read_file({"path": "hello_baize.txt"})
   0.1s .. skill_harvested distilled skill to SKILL.md
Done. I created hello_baize.txt containing 'Hello from Baize!' and read it back to verify the contents.
--------------------------------------------------------------
  run finished in 0.1s
  events: skill_harvested=1  tool=2
  outcome: final  steps=3  tools=2
--------------------------------------------------------------
```

验证文件真的存在：

```bash
$ ls -la hello_baize.txt
-rw-r--r-- 1 user user 19 Sep 17 11:00 hello_baize.txt
```

**19 字节，文件真的被创建了。**

## 3. 逐行读懂输出

### 3.1 `session: 20260917-110148-7343c5`

会话 ID，格式 `YYYYMMDD-HHMMSS-<6位随机>`。

**这个 ID 是你事后复盘一切的钥匙。** 用它可以看到：

```bash
python -m baize sessions 20260917-110148-7343c5
```

### 3.2 `0.0s -> tool write_file({...})`

`耗时 → 动作类型 工具名(参数)`。

- `-> tool` 表示"执行了一个工具"
- `.. skill_harvested` 表示"发生了一个事件"（这里是学习闭环蒸馏出了一个技能）
- 左侧的秒数是**相对本次运行的耗时**，用来快速定位是哪一步慢

### 3.3 结尾的三行摘要

```
  run finished in 0.1s
  events: skill_harvested=1  tool=2
  outcome: final  steps=3  tools=2
```

| 字段 | 含义 |
| :--- | :--- |
| `outcome` | `final`（正常结束）/ `error`（出错）/ `max_steps`（步数耗尽） |
| `steps` | 思考-行动-观察的循环轮数（这里是 3：两次工具调用 + 一次收尾） |
| `tools` | 工具调用总次数 |
| `events` | 运行期间发生的具名事件计数 |

**`outcome` 是你要看的第一件事。** 只要不是 `final`，这次运行就没有成功完成任务。

## 4. 它出错了会怎样（重要）

白泽的核心设计原则是**失败要说得清清楚楚**，绝不假装成功。

### 4.1 没配模型

```bash
$ python -m baize run "随便做点什么"
model endpoint not configured - set BAIZE_MODEL_BASE_URL / BAIZE_MODEL_NAME (and API key) in .env
💡 提示: 您可以运行 'python -m baize setup' 启动交互式快速配置向导。
```

**它直接拒绝启动**，而不是发一个注定失败的请求，也不返回一个假的"成功"。

### 4.2 模型端点连不上

真实输出（当时桩服务没启动）：

```
session: 20260917-110015-d232f0
model call failed after 3 attempts across 1 model(s): URLError: <urlopen error [WinError 10061] 由于目标计算机积极拒绝，无法连接。>
--------------------------------------------------------------
  run finished in 10.6s
  outcome: error  steps=1  tools=0
--------------------------------------------------------------
```

注意三个细节：

1. **重试了 3 次**才放弃（`BAIZE_LLM_MAX_RETRIES=2` → 1 次原始 + 2 次重试）；
2. **原样打印了底层异常**（`WinError 10061`），不美化、不吞掉；
3. `outcome: error`，明确告诉你这次没成功。

### 4.3 为什么这很重要

对比一下常见做法：

| 做法 | 结果 |
| :--- | :--- |
| ❌ 返回 `{"returncode": 0}` 假装成功 | 你在下游拿到一个空结果，排查半天 |
| ❌ 吞掉异常只打一行日志 | 日志被淹没，问题在几个版本后才发现 |
| ✅ **白泽**：明确报错 + 真实原因 + `outcome: error` | 你一眼知道该修什么 |

## 5. 常用参数

```bash
# 只打印摘要（适合脚本调用）
python -m baize run "..." --quiet

# 关掉 ANSI 颜色（适合重定向到文件）
python -m baize run "..." --no-color

# 从某个会话继续（崩溃恢复 / 分步推进）
python -m baize run "..." --resume 20260917-110148-7343c5
```

**`--resume` 的可靠性来自会话是 JSONL 落盘的**：每一步都追加写，进程被杀也不会丢历史。这是"可复现"承诺的实现方式。

## 6. 复盘：看会话里到底发生了什么

```bash
python -m baize sessions 20260917-110148-7343c5
```

**真实输出（截取）：**

```
   system: You are Baize, an autonomous engineering agent (V37.0.0 runtime). ...
     user: Relevant persistent memory: Retrieved context (RAG): - [skill 3.279] picasso-dev-maintainer (load with load_skill: ...)
assistant: I will create the file first. [tools: write_file]
     tool: wrote 18 chars -> /path/to/ws/hello_baize.txt
assistant: Now I will read it back to verify. [tools: read_file]
     tool: Hello from Baize!
assistant: Done. I created hello_baize.txt containing 'Hello from Baize!' and read it back to verify the contents.
```

**这里藏着一个非常关键的信息**：`user` 那一行显示，在任务开始之前，引擎**已经自动检索了持久化记忆和 RAG 上下文**（召回了一个叫 `picasso-dev-maintainer` 的技能，相关度 3.279），并把它注入到了提示里。

也就是说：**白泽不是每次从零开始。** 它会先查自己会什么、记得什么，再动手。这是第 05 篇的主题。

想看得更细（步骤 + 耗时谱系）：

```bash
python -m baize sessions 20260917-110148-7343c5 --inspect
```

列出最近所有会话：

```bash

```


## 7. 练习

1. **改桩服务的脚本**：让第二次返回改成调用 `list_dir`，看看输出怎么变。
2. **制造一次失败**：把桩服务停掉，再跑一次，观察 `outcome: error` 和重试次数。
3. **用 `--resume` 接着跑**：同一个会话 ID 再跑一次，看它是否延续了上下文。
4. **让它写坏代码**：把桩脚本改成写一个语法错误的 `.py`，看看引擎会不会发现。

---

## 本篇小结

- `python -m baize run "<目标>"` 是最基本的入口。
- 输出里 **`outcome` 是第一眼要看的东西**：`final` 才是成功。
- 白泽在动手前会自动召回记忆和技能（会话记录里的 `user` 行能看到）。
- 失败时它**打印真实原因**并返回 `error`，不会伪造成功。
- 每个会话都有 ID，`baize sessions <id>` 可以完整复盘。
- 代理环境下记得设 `no_proxy=127.0.0.1`。
