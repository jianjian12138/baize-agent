# 第 4 篇：白泽是怎么"思考"的 —— Agent 内核原理

> 适用读者：跑通过任务（第 3 篇），想搞懂"它内部到底怎么运转"的小白。本篇用大白话拆解 Agent 的四大机理。

---

## 4.1 一句话：它不是一个"会聊天的模型"

很多人以为 AI Agent = 大模型 + 能回话。错。白泽的 Agent 是一个**自主循环**：

```
    ┌──────────────────────────────────────────┐
    │           规划一个目标（goal）              │
    └───────────────────┬──────────────────────┘
                        ▼
              ┌─────────────────┐
              │  1. 思考(Think)  │  ← 看目标/看上一轮结果/看记忆
              └────────┬────────┘
                       ▼
              ┌─────────────────┐
              │  2. 行动(Act)    │  ← 调用一个工具（读文件/跑命令/...）
              └────────┬────────┘
                       ▼
              ┌─────────────────┐
              │  3. 观察(Observe)│  ← 拿到工具返回结果
              └────────┬────────┘
                       ▼
                 达成目标？ ──是──▶  输出结论，结束
                   │
                  否
                   ▼
              回到 1（继续循环，最多 N 步）
```

这就是经典的 **ReAct**（Reason + Act）循环，白泽把它跑到了极致，并加了"反思规划"和"记忆压缩"。

---

## 4.2 机理一：反思规划（Reflective Planning）

普通 Agent 是"走一步看一步"。白泽在**规划阶段**就会把大目标拆成子任务清单，并且在**执行过程中定期自我反思**。

- 启动时：把"为 utils.py 写测试"拆成 `读文件 → 写测试 → 跑测试 → 补遗漏` 等步骤。
- 每过 `BAIZE_REFLECT_EVERY`（默认 6）步：停下来问自己——"我还在正轨上吗？要不要调整计划？"
- 如果反思发现"卡住了/方向偏了"，会主动修正后续步骤。

> 配置开关：`BAIZE_REFLECT_EVERY=6`（设 0 关闭反思）。

**为什么这很重要**：没有反思的 Agent 容易"钻牛角尖"（一直重复同一招）。反思机制让它能**自我纠错**。

---

## 4.3 机理二：长程记忆压缩（Memory Compression）

Agent 跑久了，上下文会越来越大（所有"观察"都堆在对话里），最终会撑爆模型的上下文窗口。白泽的解法：

1. 当累计 observation 超过 `BAIZE_CONTEXT_COMPRESS_CHARS`（默认 60000 字符）时，把**旧的观察"蒸馏"成摘要**，替换掉原文。
2. 不再需要的细节被压缩掉，但**关键信息保留**，模型仍能"记得"前面干了啥。

此外，跨会话的记忆（写在 `persistence/logs/*.jsonl`）也会定期压缩：
- `BAIZE_MEMORY_COMPRESS_DAYS`（默认 30 天）：超过 30 天的日志会被蒸馏进 `notes.md`，原日志删除，释放空间。

> 命令对应：`python -m baize memory compress --days 30`

**为什么重要**：这让白泽能处理**超长任务**，而不会"前面说的都忘了"或"上下文爆炸"。

---

## 4.4 机理三：Verifier 硬化（验收者不随便放行）

这是白泽"可信"的核心。当一个子任务被 Executor 声称"做完了"，**Verifier 不会直接信**，而是：

1. 解析 Executor 给出的结论（结构化 JSON：`verdict` / `evidence` / `issues` / `session_id`）。
2. **独立用工具去验证**——比如真去跑测试、真去读生成的文件。
3. 还支持"确定性检查"（checks）：比如"这个接口必须返回 200"，Verifier 会真的发请求确认。
4. 如果验证不通过：把问题（`issues`）**注入回 Executor 的修复目标**，进入**有界重试**（最多 `BAIZE_LLM_MAX_RETRIES` 次）。
5. 循环检测：如果发现 Agent 在**重复同样的工具调用**（窗口 `BAIZE_LOOP_DETECT_WINDOW` 默认 3 次），会预警，防止死循环。

> 这一套保证了：**白泽说"做完了"，是真的做完了，或者它明确告诉你"没做成"。**

---

## 4.5 机理四：会话即事实（JSONL 持久化）

每一次运行，白泽会把所有事件（思考、工具调用、观察、反思）**按时间顺序追加写**进一个 JSONL 文件：

- 路径在 `persistence/sessions/<session_id>.jsonl`
- 格式是 append-only（只追加，不覆盖）

好处：
- **崩溃不丢状态**：程序挂了，日志还在，可以 `--resume` 续跑。
- **可审计**：事后能完整回放"它到底干了啥、按什么顺序"。
- **可复现**：同样的目标 + 同样的日志，可以重放。

查看历史会话：

```bash
python -m baize sessions               # 列出所有会话
python -m baize sessions <session_id>  # 查看某次会话的完整转录
```

## 4.6 一个最小的"内心戏"示例

假设你说：`python -m baize run "给 config.py 加一个读取 BAIZE_FOO 的配置项"`

白泽内部大致经历（简化）：

```
[plan]    把目标拆成：1)读 config.py  2)加 BAIZE_FOO 默认值  3)验证可被读取
[think]   我先读一下 config.py 看现在结构
[act]     read_file(config.py)
[observe] 读到 _DEFAULTS 字典，里面有 BAIZE_PERSISTENCE_DIR 等
[think]   好，我在 _DEFAULTS 里加一行 "BAIZE_FOO": ""
[act]     write_file(config.py, 加上新行)
[observe] 写入成功
[act]     bash("python -c \"import baize.config; print(baize.config.load_config()['BAIZE_FOO'])\"")
[observe] 输出空字符串 "" —— 说明配置项可被正确读取
[reflect] 目标达成，且验证通过
[final]   已在 config.py 加入 BAIZE_FOO，验证可读，值为 ""
```

每一步你都能在 TUI 上看到。这就是"白盒"。

## 4.7 配置速查（Agent 行为调优）

| 配置项 | 默认 | 作用 |
|--------|------|------|
| `BAIZE_AGENT_MAX_STEPS` | 24 | 单次运行最多循环次数（防失控） |
| `BAIZE_REFLECT_EVERY` | 6 | 每几步自我反思一次（0=关闭） |
| `BAIZE_LOOP_DETECT_WINDOW` | 3 | 连续重复几次相同工具调用就预警 |
| `BAIZE_CONTEXT_COMPRESS_CHARS` | 60000 | 累计观察超此字符数就压缩旧内容 |
| `BAIZE_MEMORY_COMPRESS_DAYS` | 30 | 多少天的日志进 notes.md 压缩 |
| `BAIZE_LLM_MAX_RETRIES` | 2 | 模型调用失败重试次数 |

---

## 4.8 本篇小结

- 白泽 Agent = **自主 ReAct 循环**：思考 → 行动 → 观察 → 循环。
- **反思规划**：先拆目标，执行中定期自我纠错。
- **长程记忆压缩**：旧观察蒸馏成摘要，能跑超长任务。
- **Verifier 硬化**：独立用工具验证，失败有界重试，杜绝"假完成"。
- **会话即事实**：JSONL 持久化，崩溃可续跑、可审计、可复现。
