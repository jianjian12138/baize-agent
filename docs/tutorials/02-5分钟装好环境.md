# 02 · 5 分钟装好环境

> 目标：从零把环境装好，让 `python -m baize doctor` 亮起 **`RESULT: PASSED`**。
> 本篇所有命令都在真实环境跑过，输出是实测粘贴的。

---

## 0. 先看要求

| 项目 | 要求 | 说明 |
| :--- | :--- | :--- |
| Python | **>= 3.10** | `doctor` 的第一个检查项。3.13 实测可用。 |
| 操作系统 | Windows / macOS / Linux | Windows 上 OS 沙箱会降级（见第 1.3 节） |
| 网络 | 装的时候需要 | 装完之后只有调用模型才需要 |
| 大模型 | **自备** | 任意 OpenAI 兼容端点 |

**不需要**：Node、Go、Docker、任何 Python 第三方包。

## 1. 安装

### 1.1 方式 A：一键安装脚本（推荐）

```bash
python install/bootstrap.py
```

这个脚本会：
1. 检查 Python 版本是否 >= 3.10；
2. 如果没有合适的 Python，尝试自动装一个（winget / Homebrew / apt-dnf-apk / python.org）；
3. 用新解释器**重启自己**；
4. 安装依赖（本项目没有运行时依赖，这一步只是把它装进环境）；
5. 跑环境门禁 `doctor`。

常用参数：

```bash
python install/bootstrap.py --test            # 顺便跑测试套件
python install/bootstrap.py --skip-doctor     # 跳过环境门禁
python install/bootstrap.py --no-auto-python  # 绝不自动装 Python
```

平台专用脚本：`install/install.sh`（Linux/macOS）、`install/install.bat`（Windows）、`install/setup.sh`。

### 1.2 方式 B：手动（想完全掌控每一步时）

```bash
git clone https://github.com/jianjian12138/baize-agent.git
cd baize-agent
git checkout v30-dev          # ← 重要：默认开发分支是 v30-dev

# 建虚拟环境
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate

# 可编辑安装（不会拉任何第三方运行时依赖）
pip install -e .
```

> 💡 为什么强调 `git checkout v30-dev`？因为仓库有两条互不合并的历史线（见第 01 篇第 6 节）。`v30-dev` 才是活跃开发线。

### 1.3 方式 C：零安装直接用

因为零依赖，你甚至可以直接跑：

```bash
python -m baize --version
```

只要当前目录是仓库根，Python 就能找到 `baize/` 包。

## 2. 配置：让 doctor 亮绿灯

### 2.1 复制环境模板

```bash
cp .env.example .env
```

> **⚠️ 这一节曾经是新手最大的坑，现在已经修好了。**
>
> 旧版 `.env.example` 里的默认值是：
> ```
> SKILL_LIBRARY_PATHS=./assets/skills,./picasso-dev-skill,./skills
> ```
> 后两个目录在仓库里**根本不存在**。而同一个文件的注释又写着"缺失路径会让 doctor 失败"——所以照着文档做，`doctor` 必定报错。
>
> 现在默认值已经改成只包含真实存在的 `./assets/skills`。

### 2.2 配置大模型

编辑 `.env`，填入你的模型端点：

```bash
BAIZE_MODEL_BASE_URL=https://api.openai.com/v1
BAIZE_MODEL_NAME=gpt-4o-mini
BAIZE_MODEL_API_KEY=sk-your-key-here
```

**任何 OpenAI 兼容的 chat-completions 端点都行**：OpenAI、OpenRouter、Ollama、vLLM、自建网关……

或者用交互式向导：

```bash
python -m baize setup
```

> 💡 没配模型会怎样？`baize run` 会**拒绝启动**并告诉你怎么办，而不是发一个注定失败的请求：
> ```
> model endpoint not configured - set BAIZE_MODEL_BASE_URL / BAIZE_MODEL_NAME (and API key) in .env
> 💡 提示: 您可以运行 'python -m baize setup' 启动交互式快速配置向导。
> ```

## 3. 环境门禁：doctor

```bash
python -m baize doctor
```

**真实输出（修复后）：**

```
Baize Doctor Report
========================================
[PASS] python>=3.10  - found 3.13
[PASS] .env present  - /path/to/repo/.env
[PASS] dir BAIZE_PERSISTENCE_DIR  - /path/to/repo/persistence
[PASS] dir BAIZE_PROJECTS_DIR  - /path/to/repo/projects
[PASS] dir BAIZE_ASSETS_DIR  - /path/to/repo/assets
[PASS] persistence writable  - /path/to/repo/persistence
[PASS] skill library assets/skills  - assets/skills
[PASS] tool git  - on PATH
[PASS] tool node  - on PATH
[WARN] tool go  - not found (optional)
[WARN] os sandbox  - mechanism=logical-only (degrades to logical-only; OS shield unavailable here)
[PASS] config schema  - all set values are well-formed
========================================
RESULT: PASSED
```

### 3.1 逐项解释

| 检查项 | 含义 | FAIL 了怎么办 |
| :--- | :--- | :--- |
| `python>=3.10` | 解释器版本 | 装个新 Python |
| `.env present` | 配置文件在不在 | `cp .env.example .env`（WARN 不阻塞） |
| `dir BAIZE_*_DIR` | 三个核心目录是否存在 | 见下方 3.2 |
| `persistence writable` | 真写一个临时文件进去试 | 检查目录权限 |
| `skill library ...` | 技能库路径可达 | 检查 `.env` 里的 `SKILL_LIBRARY_PATHS` |
| `tool git/node/go` | 可选工具 | 非阻塞，`go` 没有也不影响 |
| `os sandbox` | OS 级沙箱能力 | 非阻塞，见 3.3 |
| `config schema` | 配置值格式对不对 | 看提示改 `.env` |

### 3.2 `dir BAIZE_PROJECTS_DIR` 曾经必定 FAIL

**这是本篇最重要的排错知识。**

`doctor` 要求 `BAIZE_PROJECTS_DIR`（默认 `./projects`）必须存在，标记为 `required=True`。
但 `.gitignore` 里原本写的是：

```
projects/
```

**整个目录被忽略** → 新克隆的仓库里没有这个目录 → `doctor` 必定 FAIL → 文档宣传的"1 分钟极速上手"永远走不通。

现在 `.gitignore` 改成：

```
projects/*
!projects/.gitkeep
```

也就是：**目录本身进仓库，目录内容仍然被忽略**。所以现在 `cp .env.example .env` 之后 `doctor` 直接 `RESULT: PASSED`。

> 如果你用的是老版本仓库并且遇到这个 FAIL，手动建目录即可：
> ```bash
> mkdir -p projects
> ```

### 3.3 关于 `os sandbox - mechanism=logical-only`

这条 WARN 在 Windows 上是**正常的**，不是故障。

`baize/sandbox.py` 的实现原则是**诚实降级**：

| 平台 | 机制 | 说明 |
| :--- | :--- | :--- |
| Linux | Landlock（Python 3.13+） | 内核级文件访问控制 |
| macOS | Seatbelt（`sandbox-exec`） | 系统级沙箱 |
| Windows | **logical-only** | 只做 deny-list + 工作区约束 |

Windows 的受限令牌实现成本极高，项目选择**明确告诉你它没有硬隔离**，而不是假装有。文件里的原话是：*"We never claim OS isolation we do not have."*

想开启 OS 沙箱（Linux/macOS）：

```bash
BAIZE_SANDBOX_ENABLED=1
```

## 4. 验收：跑一遍全部门禁

```bash
make gate
```

等价于按"便宜的检查先跑"的顺序执行：

```
deps     →  python scripts/check_zero_deps.py      # 零依赖契约
truth    →  python scripts/sync_truth.py --check   # 版本/测试数一致
hygiene  →  python scripts/check_hygiene.py        # 没有垃圾文件被提交
cov      →  python scripts/coverage_gate.py        # 覆盖率下限
```

**预期结果**：

```
ZERO-DEP CHECK PASSED: baize/ imports stdlib only at module level (5 optional import(s) allowed)
TRUTH CHECK PASSED: V37.0.0 Prometheus, 1335 tests collected, 13 count claims verified, no drift
HYGIENE GATE PASSED: 344 tracked files, none matching a banned pattern
COVERAGE GATE PASSED: <本次实测>% >= 85%
```

> **四行都应该是 PASS。** 如果覆盖率那行报 `cannot verify`，说明覆盖率数据文件比源码还旧——先跑 `make cov` 再跑门禁。门禁不会拿一份旧数据给出结论。
>
> 覆盖率低于 85% 时它会报 `COVERAGE GATE FAILED`。想让它变绿的正确做法是**补测试**，不是把 `TEST_COVERAGE_THRESHOLD` 改小。`tests/test_config.py` 有一条测试专门钉住这个值（`assert cfg["TEST_COVERAGE_THRESHOLD"] == "85"`），就是为了防止有人用"改小目标"来伪造绿色。
>
> 用例数、跟踪文件数这些数字每次提交都会变；`make gate` 打印的永远是你当前这棵树的值。上面那两处具体数字（`1335` / `344`）以及 `13 count claims` 都被 `scripts/sync_truth.py` 的 count claim 钉住了，漂了它会逐条报出来——这段文字自己也不例外。
>
> 覆盖率那个百分比是**唯一不写固定值**的：它不是提交的属性，而是**环境**的属性。同一个提交，工作树实测 86.9%、全新克隆 86.8%，差在 `serve.py` / `cli.py` 里那 6 行（是否有一份被 gitignore 的 `.env`）。写死任何一个都会在另一棵树上错，所以这里只写契约（`>= 85%`），当前值用 `make cov` 看。

## 6. 常见问题

**Q：`python` 命令找不到？**
用 `py -3` （Windows）或 `python3`（Linux/macOS）代替。或者直接用绝对路径。

**Q：`doctor` 报 `skill library ... not found`？**
打开 `.env`，把 `SKILL_LIBRARY_PATHS` 里不存在的路径删掉。只保留真实存在的目录。

**Q：`doctor` 报 `config schema` FAIL？**
说明 `.env` 里某个值格式不对（比如端口写了非数字）。报错信息会指出具体是哪个键。

**Q：`make` 命令不存在？**
Windows 上没有 `make`，直接用 `python scripts/xxx.py` 逐个跑即可。

**Q：pip 安装很慢 / 失败？**
本项目**没有运行时依赖**，`pip install -e .` 只做本地打包，不需要下载任何包。如果很慢，说明 pip 在查索引——加 `--no-index --no-build-isolation` 试试。

## 本篇小结

- 安装有三条路：`install/bootstrap.py`（一键）、手动 `pip install -e .`、或者零安装直接 `python -m baize`。
- **记得 checkout `v30-dev` 分支**。
- `cp .env.example .env` 之后 `doctor` 应该直接 `RESULT: PASSED`。
- `make gate` 的最后一项（覆盖率）**预期是 FAIL**，这是公开的已知缺口，不是你的环境坏了。
- `baize bench` 15/15 通过就说明环境健康。
