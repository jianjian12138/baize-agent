# 白泽引擎 V19 重构交付报告

> 版本：**V19.0.0** ｜ 交付方：白泽引擎乙方研发团队（专家会诊组）
> 重构动因：V18 已通过甲方验收，但一线 `agent 工程师` 反馈「与理想中的 Agent 差距仍大」
> ——他们要的是对 **hermes-agent + pi** 的**功能整合与升级**：学习二者被验证的核心设计，
> 而不是套壳复刻，是在白泽既有优势上做**升级**。
> 参考：<https://pi.dev/> ｜ <https://github.com/NousResearch/hermes-agent>

---

## 一、重构动因与定位

| 视角 | 上一版（V18）状态 | 理想 Agent 落差 |
|------|------------------|----------------|
| 运行形态 | 规约 + 校验工具（doctor / 索引 / manifest / 记忆） | 缺少**可自主运行的 Agent 内核**：不能自驱动「思考→工具→观察」循环 |
| 模型接入 | 无独立 LLM 客户端 | 缺**模型无关**调用层，无法脱离外部客户端独立工作 |
| 多 Agent | 无 | 缺 **Director→Executor→Verifier** 编排与独立核验门禁 |
| 会话/记忆 | 记忆 CLI 有，但 Agent 未用 | 缺 **JSONL 会话持久化**，运行中不可审计、崩溃丢状态 |

**V19 定位**：在 V18「规约 + 校验工具」的双层架构之上，**新增一层纯 stdlib 自研的 Agent 运行时**，
把白泽从「被加载的规约包」升级为「可独立运行、可编排团队的 Agent 系统」，同时保留并激活
白泽独有的 doctor / manifest / 技能生态 / 持久记忆门禁。

## 二、从 hermes-agent 与 pi 学到的核心设计（并升级）

| 来源 | 学到的被验证设计 | 白泽 V19 的升级实现 |
|------|------------------|---------------------|
| hermes | 自主循环（reason→tool→observe→repeat） | `agent.py` 实现自主循环；**启动时自动注入技能索引 + 相关持久记忆**（环境感知启动） |
| hermes | 模型无关客户端 | `llm.py` 用 OpenAI 兼容 chat-completions，transport 可注入，任意端点可替换 |
| hermes | 自进化技能（save_skill） | 9 工具含 `save_skill`：**落盘即重建索引**，全体 Agent 立即可检索 |
| pi | 极简内核 + 原语工具 | 保持**零第三方依赖** stdlib；`tools.py` 工具注册表运行时可扩展 |
| pi | JSONL 会话持久化 + checkpoint | `agent.py` append-only JSONL；叠加 **多 Agent 编排**：每个角色独立会话，全链路可审计、可 `--resume` |
| 白泽独有 | — | **Verifier 独立核验门禁**、**manifest 证据物理核验**、**doctor 环境门禁**、**249 唯一技能生态**、**双模式**（可被 Claude Code / Codex / WorkBuddy 加载，也可自主运行） |

> **非套壳**：全部运行时代码为纯标准库自研，无 `pip` / `npm` 运行时依赖；
> 有 69 个真实 pytest（脚本化 transport 真实驱动整条循环，无 MagicMock 屏蔽）与 openspec 规格背书。

## 三、架构升级：新增 4 个运行时模块

```
┌──────────────────────────────────────────────────────────┐
│  第一层：规约与技能（被 AI 客户端加载，或注入 Agent 提示词）│
│  AGENT.md（操作协议） SKILL.md（流水线规约）              │
│  外部技能库（SKILL_LIBRARY_PATHS，249 唯一技能）          │
├──────────────────────────────────────────────────────────┤
│  第二层：baize 运行时（纯 stdlib，零第三方依赖）          │
│                                                          │
│  ◆ Agent 内核（V19 新增）                                │
│    llm          模型无关 OpenAI 兼容客户端（任意端点）    │
│    tools        工具注册表：9 内置工具 + 沙箱 + deny-list │
│    agent        自主循环：思考→工具→观察→迭代             │
│                 JSONL 会话持久化，崩溃可 --resume 续跑    │
│    orchestrator Director→Executor→Verifier 多 Agent 编排 │
│                 验证失败自动带 issues 重试（NO FAKE DONE）│
│                                                          │
│  ◆ 校验与记忆（V18 保留并激活）                          │
│    doctor       环境门禁（真实探测，真实退出码）          │
│    skill index  技能索引与检索（3 来源去重）              │
│    manifest     流水线门禁（证据文件必须物理存在）        │
│    memory       跨会话持久记忆（多关键词+tags+相关性评分）│
└──────────────────────────────────────────────────────────┘
```

### 3.1 `llm.py` — 模型无关客户端
- `LLMClient(cfg, transport=None)`：OpenAI 兼容 `/chat/completions`，模型无关。
- `chat(messages, tools, temperature)` 返回 `{role, content, tool_calls?}`。
- **transport 可注入**：测试用脚本化假 transport 真实驱动整条循环（确定性、无网络）。
- `configured` 属性；未配置端点时 `run`/`team` **明确拒绝并 exit 2**。

### 3.2 `tools.py` — 工具注册表 + 沙箱
- `ToolRegistry` + `default_registry()` 注册 **9 个原语工具**：
  `read_file` / `write_file` / `list_dir` / `bash` / `search_skills` / `load_skill` / `memory_recall` / `memory_log` / `save_skill`。
- **沙箱**：所有文件操作限制在 `BAIZE_WORKSPACE_DIR`（`_resolve_in_workspace`）；
  `BAIZE_ALLOW_OUTSIDE_WORKSPACE=0` 时越界操作被拒。
- **deny-list（fail-closed）**：`DENY_PATTERNS` 覆盖危险命令（rm -rf / 格式化 / 删系统目录等），
  默认拦截、默认拒绝（fail-closed），`command_allowed` 把关。

### 3.3 `agent.py` — 自主循环 + 会话持久化
- `Agent.run(goal)` 返回 `AgentResult`；思考→工具→观察迭代，`BAIZE_AGENT_MAX_STEPS`（默认 24）上限防失控。
- **环境感知启动**：`build_system_prompt(role, cfg, registry, extra)` 自动注入技能索引 + 相关持久记忆（`recall_context`）。
- **会话即事实**：`Session` 以 append-only JSONL 落盘（`persistence/sessions/`），崩溃不丢状态；
  `python -m baize run ... --resume <session_id>` 可续跑；`list_sessions()` 可审计回放。

### 3.4 `orchestrator.py` — 多 Agent 编排
- `Orchestrator.plan()` 拆解任务 → `Orchestrator.run()` 调度
  **Director（规划）→ Executor（执行）→ Verifier（核验）** 三角色，每个角色独立会话。
- **NO FAKE DONE 可执行化**：Verifier 独立取证核验；失败自动带 `issues` 重试（`max_retries_per_task`）；
  全部通过才标记完成。`run()` 返回 `OrchestratorResult`。

## 四、关键能力清单（V19 新增）

1. **自主 Agent 内核** —— `baize run "<目标>"` 单 Agent 自驱动开发工作。
2. **多 Agent 团队** —— `baize team "<目标>"` Director→Executor→Verifier 协作，失败自动重试。
3. **会话持久化与续跑** —— `baize sessions` 列出/回放；`--resume` 续跑，崩溃可恢复。
4. **技能自进化** —— `save_skill` 落盘即重建索引，学习成果即时沉淀、全员可用。
5. **工具沙箱 + deny-list** —— 工作区限制 + 危险命令 fail-closed 拦截，默认安全。
6. **模型无关** —— 任意 OpenAI 兼容端点，transport 可注入便于确定性测试。
7. **双模式** —— 既可被 Claude Code / Codex / WorkBuddy 作为规约包加载，也可独立运行。
8. **门禁全激活** —— doctor（环境）/ manifest（证据物理核验）/ Verifier（独立核验）/ memory（持久记忆）四重保障。

## 七、与 hermes-agent / pi 对标摘要

完整矩阵见 `benchmarks/COMPARISON.md`。V19 在以下维度实现**整合升级**，且为二者所无：

- **独立核验门禁**：Verifier 独立取证 + 失败自动重试（hermes/pi 均无内置）。
- **流水线证据物理核验**：manifest validate 强制证据文件物理存在（hermes/pi 均无）。
- **技能自进化即时生效**：`save_skill` 落盘即重建索引，全体 Agent 立即可检索。
- **双模式运行**：既能被外部客户端加载为规约包，也能独立 `run` / `team` 运行。
- **零运行时依赖**：纯标准库，仅测试期需 pytest/coverage；hermes 需 pip、pi 需 npm/pip。
- **方法论内置**：毛选调查 + 卡帕西编码可加载、可注入。
