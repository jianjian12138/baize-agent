## 1. 升级计划总览

### 1.1 目标版本

**Baize Agent V25.0.0**（V24.0.0 → V25 生态接入 + 可见性增强，非新建、非重构）

> **版本号裁决（U-03，经中间确认·已裁决）**：bump 至 25.0.0。理由：项目惯例 V{N}→{N}.0.0 对齐（V22/V23/V24→24.0.0）；V25 引入 MCP 生态接入是显著功能增量，major bump 语义合理；避免"V25 升级但 baize --version 仍 24.0.0"的认知割裂。影响 8 处版本字符串（pyproject.toml / manifest / __init__.py / README / Dockerfile LABEL / .env.example 头部 / 全部 docs 头部）。

### 1.2 升级主题

**V25 = 生态接入 + 可见性**（不破坏零依赖红线）

- **生态接入**：MCP 兼容（既能调外部 MCP server，也能暴露 baize skills 给 Claude Desktop/Cursor）、模型供应商补丁、多智能体薄配置层
- **可见性**：GitHub 元数据止血、README 重写、文档/版本号全量统一

### 1.3 价值定位

升级后 Baize 将成为唯一**「纯 stdlib 零依赖 + NO FAKE DONE 可验证门禁 + MCP 兼容」三者兼得**的 Agent 运行时。

## 5. 演进纪律与约束红线（来自 M3 高层架构 §4.3）

### 5.1 演进纪律

- MVP 架构是 V26 子集，**不推倒重来**
- 核心 `baize/` **永不 import ext**（静态 grep 门禁 CI 强制）
- **不迁移核心适配器**到 ext（X6）
- **不另造平行抽象**（X7）
- 外科手术式变更（最小 diff，无关代码零改动）

### 5.2 约束红线 A–E

| 红线 | 内容 | 落实机制 |
| --- | --- | --- |
| A | 运行时零第三方依赖：核心 baize/ 永远纯 stdlib；ext 延迟 import + fail-closed | CI ast 扫描 + 静态 grep 门禁 |
| B | NO FAKE DONE：done 须有物理 evidence；Verifier 独立核验；不声称覆盖率（要么真跑给实数，要么标 UNKNOWN） | manifest + gate + doctor + pytest |
| C | baize/ext/ fail-closed：默认不启用、核心不触碰；ext 测试 importorskip 守卫；norecursedirs 补 ext | pyproject + importorskip |
| D | 外科手术式变更 + 显式优先：最小 diff；BAIZE_MODE/BAIZE_COMPONENTS 优先于标量滑块 | 代码评审 + gate |
| E | fail-closed 安全观：沙箱默认开 + deny-list + 未配置 exit 2 + 插件绝不默认可信 | sandbox + config_schema + plugin |

## 6. 系统设计要点（来自 M4 系统设计）

### 6.1 模块拆分（6 模块）

| 模块 | 职责 | 关键接口 |
| --- | --- | --- |
| M1 MCP 兼容 | baize/ext/mcp/（transport/client/server） | stdio JSON-RPC 2.0 + Content-Length 分帧 + initialize 握手 |
| M2 Team 薄配置层 | baize/team.py | role→system_prompt+tools 映射，复用 orchestrator |
| M3 Provider 补丁 | baize/ext/providers/ | provider_capabilities 如实上报；Anthropic max_tokens 参数化 |
| M4 可见性管理 | README/docs/Dockerfile/.env.example | 版本号全量统一 25.0.0 |
| M5 统一扩展总线 | plugin.discover + CompositionKernel.add_component | 收口点，禁各阶段自起 import |
| M6 ext 测试守卫 | pyproject + importorskip | norecursedirs 补 ext |

### 6.2 接口契约锁定

- **MCP**：stdio JSON-RPC 2.0 + Content-Length 分帧 + initialize 握手（protocolVersion 协商 + capabilities 交换 + notifications/initialized）
- **统一抽象**：`complete(messages, **kw) -> (text, usage)`
- **收口路径**：显式覆盖（BAIZE_COMPONENTS）+ 自动发现（plugin.discover），唯一例外 `tools.register_mcp_client` 函数体内延迟 import
