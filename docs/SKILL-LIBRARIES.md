# 技能库结构说明（Skill Libraries）

白泽的技能来自三个**相互独立**的技能库，由 `skill_index` 在构建索引时统一发现、检索与去重。本文件说明它们的角色边界与命名约定，避免对磁盘上的"命名变体"误判为缺陷而去批量改名（会破坏外部一致性与索引去重的保留/丢弃选择）。

## 1. 三个技能库

| 库 | 路径 | 角色 | 索引计数（V24 核验）|
|----|------|------|------|
| 内置方法论技能 | `assets/skills/` | 白泽自带的方法论 / 战略技能（毛选战略、卡帕西编码、picasso-dev 系列等）| 23 |
| picasso-dev 插件工程 | `picasso-dev-skill/` | 一个**独立工程**（含 `.claude-plugin` / vendor / install / profiles 等），本身并非纯技能库；作为技能来源之一被索引 | 7 |
| 外部技能中心 | `skills/` | 大型外部引入的技能集合（约 240 个目录），通过 `SKILL_LIBRARY_PATHS` 配置化引用，不复制到项目内 | 220 |

> `picasso-dev-skill/` 是独立仓库/工程，保留其原始工程结构；它只是"恰好也是技能来源"。不要在白泽侧把它当成普通技能库去重构。

## 2. 去重机制（V23.1，功能层已统一）

`skill_index._dedup` 在构建索引时：

- 按**归一化名称**（忽略大小写与 `-` / `_` 分隔符）把同名技能聚成"跨库重复组"；
- 每个组保留**最规范副本**（优先带真实 frontmatter 描述、内容更完整），丢弃其余副本；
- 核验结果：唯一技能 **250** 个，去重丢弃 **52** 个副本，跨库重复组 **30** 个。

因此磁盘上 `api-tester` / `apitester`、`test-manager` / `test_manager` 这类**命名变体是预期冗余**——索引层已将其合并为同一技能对外暴露，无需在磁盘上改名。强行改名反而会让索引去重失去"保留/丢弃"的判定对象，并破坏外部上游一致性。

## 3. 统一化约定（V24）

- 三个库的**角色与磁盘命名保持现状**：`skills/` 作为外部引入集合，保留上游原始命名（含 kebab 与 snake_case 混用），白泽侧**不批量改名**。
- 白泽**自有**的 `assets/skills/` 维持其既有命名约定；新增技能统一写入 `user_skills/`（`BAIZE_USER_SKILLS_DIR`，V23.2 起），与内置收集库解耦，避免污染内置库。
- 若确需清理某个磁盘命名变体，必须先确认两份内容**完全一致**，并用 `baize skill audit` 评估、保留 git 历史后再操作（破坏性去重须谨慎）。

## 4. 相关命令

```bash
python -m baize skill audit     # 查看去重组 / 缺失 frontmatter 报告
python -m baize skill search <kw>
python -m baize index build
```
