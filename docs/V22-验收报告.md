## 四、发现与修复清单（F1–F5，均已闭环）

### 🔴 F1 — 自动发现组件"默认不可信"不彻底（HIGH） → ✅ 已修复

**初验现象**：`add_component(explicit=False)` 直接覆盖内置默认；`assemble()` 仅做签名校验，构建成功且结构合法的组件被直接信任并替换活动组件（含 SANDBOX/TOOL/SESSION），部分继承 deepseek-harness 弱点②。

**修复**：`component.py` 引入 `SECURITY_CRITICAL_KINDS = {sandbox, tool, session}`。`add_component` 对自动发现（`explicit=False`）组件，若其 kind 属安全关键，**直接拒绝**（保留内置默认 + 日志 `REJECTED`），仅显式 `BAIZE_COMPONENTS`（`explicit=True`，fail-closed）可覆盖。模块文档"默认不可信"现已在成功路径上成立。

**复验（Agent 工程师 / 架构师）**：注入恶意 `SANDBOX` 自动组件 → 被拒绝、内置 `_SandboxAdapter` 保留；显式 `Good` 覆盖仍生效；`tests/test_component.py::test_security_critical_kinds_reject_auto_discovery` 与 `tests/test_plugin_discovery.py` 两项断言通过。✅ **消除弱点②**。

### 🟠 F2 — 配置校验漂移，信任边界键静默 fail-open（MED-HIGH） → ✅ 已修复

**初验现象**：`config_schema.py` SCHEMA 仅 45 条，11 个信任边界键未校验，无效值静默穿透 `validate()`。

**修复**：补齐 11 键 —— `BAIZE_SANDBOX_ENABLED / BAIZE_PLUGINS_DIR / BAIZE_HOOKS_FILE / BAIZE_MCP_ENABLED / BAIZE_MCP_SERVERS / BAIZE_PLAN_MODE / BAIZE_AUTONOMY / BAIZE_AUTONOMY_COST_CAP / BAIZE_PROMPT_CACHE / BAIZE_AUTOMATIONS_FILE / BAIZE_AUTOMATIONS_POLL_SECONDS`，按 `bool / enum / int_range / json_or_empty / path / any` 正确校验。

**复验（Agent 工程师）**：`pytest tests/test_config_schema.py -q` → **10 passed**；坏值实验全部 `raise ConfigError`。✅

### 🟡 F3 — 诚实门禁 `check_composition` 为烟雾级（MED） → ✅ 已修复

**初验现象**：仅校验 mode 的 bundle key 存在，不实例化 loop，fail-open。

**修复**：`gate.py::check_composition` 对每个 `VALID_MODES` 解析 `b["loop"]` 并调用 `agent.get_loop_strategy()` 真正实例化，断言 `isinstance(..., LoopStrategyProto)`；未知 loop 名 `ValueError`。4 个 mode（coding/eval/autonomous/safe-review）均实例化且符合协议。

**复验（架构师）**：将某 mode 指向不存在的 loop → gate `FAIL`（不再 fail-open）。✅

### 🟡 F4 — 组合内核与核心 Agent 循环脱节（MED） → ✅ 已修复

**初验现象**：工具执行不经 `Kind.TOOL`；`assemble()` 回退 `except: return` 可能留 `None` 空洞。

**修复**：`agent.py` 工具注册表经 `get_runtime().get(Kind.TOOL)` 解析（显式 override 被尊重），异常时安全回退 `default_registry()`；`component.py::assemble` 末尾做 fail-closed 完整性检查，任何 kind 缺失即 `raise ComponentError`。

**复验（Agent 工程师 / 架构师）**：`pytest tests/ -q` 全绿；删除 STORAGE 组件 → `ComponentError` 抛出（无 None 洞）。✅

### 🟡 F5 — 部分模块覆盖率偏低（MED） → ✅ 已修复

**初验现象**：cli 74% / serve 75% / context 72% 存在未测路径。

**修复**：新增 `tests/test_f5_gap.py`（15 项），覆盖 cli `cmd_gate`/`cmd_bench(public)`/`cmd_automations` 全部分支、context 的 Anthropic 块提取 / 去重 / 空内容 / load 边界、serve 的 `/bench`/`/gate`/`/sessions/<id>`/`/sessions/fork`/`/sessions/compress` 路由。

**复验（测试工程师）**：cli **97%** / serve **100%** / context **97%** / total **91%**（均 ≥ 85% 阈值）。✅

## 六、残余风险与跟踪建议（非阻塞，放行前已知会）

1. **结构性协议的理论性缺口（架构师提出）**：`runtime_checkable` Protocol 仅验方法签名。F1 已对**执行 + 持久化边界（sandbox/tool/session）**彻底封堵（自动组件直接拒绝，仅显式 override 可替换）。但**非安全关键 kind（model/ui/scheduler/storage/skill/loop）** 仍接受经"结构校验"的自动发现组件——行为恶意但签名合法的插件理论上可混过。
   **建议（后续，非放行阻塞）**：对非关键 kind 的自动加载组件补充行为契约测试，或扩展信任闸门。
